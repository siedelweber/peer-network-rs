## Build graph · `sec:buildgraph:record`

**Decision (Composition)** · `dec:buildgraph:composition` Meson composes the gate and Ninja executes its dependency graph; Cargo remains the Rust build and test driver, feature resolver and build-cache coordinator. A root meson.build composes explicit per-directory file lists and step targets, so a change to a gate input or dependency is a reviewable graph change. Meson does not reproduce Cargo's internal dependency resolver or replace the deployed linter. Preserve the pinned compiler and reviewed profiles under (`rec:toolchain:decision`), the test contracts under (`rec:testing:decision`) and nonverdict timing under (`rec:devperf:decision`). An opaque target that invokes the whole existing gate would hide the dependencies this decision requires; a second independent list of shell commands would let the two gates drift.

**Rule (Declared inputs and outputs)** · `rule:buildgraph:edges` Each step declares its executable and imported helper closure, explicit tracked input paths, upstream artifacts, output reports, build outputs, working directory, features, profile and environment requirements. Directory names in (`tab:buildgraph:steps`) designate sets to enumerate in those lists, not recursive glob dependencies. Include manifests, lockfile, compiler configuration, fixtures, templates and policy declarations as well as code. Record external tools and services as prerequisites with answering versions and public configuration; secret values never enter the graph or its reports. Cargo owns artifact freshness internally, but the outer graph still records its source and configuration envelope and every consumer edge. A file declared in a list but connected to no consumer or justified exclusion is a structural finding. A new file or step must update its declaration in the same change.

**Rule (Fresh execution)** · `rule:buildgraph:freshness` Migrate each named step as an always-run Meson custom target with a per-invocation report, using build_always_stale rather than a cached successful test verdict. The initial graph preserves the existing serial order as explicit dependencies, including repeat document checks and service lifetimes; Cargo continues to reuse valid build artifacts. Source identity alone is not a run identity: clear or isolate prior reports and bind every report to the current invocation, source, toolchain and execution configuration. The linter census also runs afresh even when configuration has not changed, so an unlisted addition cannot hide behind a clean Ninja cache. No successful stamp from an earlier run supplies claim evidence. A later incremental or parallel execution policy needs its own equivalence evidence before adoption.

**Rule (Result propagation)** · `rule:buildgraph:results` A step adapter publishes the command's actual exit status, stdout, stderr and measurement even on refusal. Its report target can finish successfully after publishing a failing command result, allowing independent checks to continue as the shell gate does; this is completion of reporting, never a success stamp for the command. Consumers requiring a successful producer check that producer's current report and record a blocked result if it failed; missing, malformed or stale reports are structural failures. The final target reads every required step result and fails on any failed, blocked or missing obligation. Adapter failure cannot be hidden by an old report. Preserve advisory-only findings as advisory and existing bounded-operation refusal tests as tests; do not add Meson or Ninja test timeouts that turn an elapsed budget into failure (`rule:devperf:nonverdict`).

## File accounting · `sec:buildgraph:census`

**Rule (Tracked census)** · `rule:buildgraph:census` The deployed linter's census compares explicit declared and excluded path lists with the tracked checkout on every gate invocation. Supply --root, --declared, --excluded and --pattern; use the deployed --report and --stamp interface only with its declared semantics, never assume another tool version's option names. Use a pattern that matches no paths initially: a broad directory or suffix exclusion would silently admit new unconsumed files. Refuse missing or stale declarations, duplicate declarations, invalid tracked modes and unexpected checkout paths under the existing tracked-exclusive policy. In addition, the graph's incidence check reconciles the complete Git tracked set with its declared consumers and individually justified exclusions, including tracked paths ignored by a carrier policy; a carrier ignore is not a graph exemption. The implementation slice tests both directions and disjoint declared/excluded lists. A path census establishes file accounting, not that a command actually reads every byte or that its declared dependencies are semantically complete.

**Convention (Vendor exclusions)** · `conv:buildgraph:vendor` Vendor files remain individually accounted for. Sources, manifests, licences and fixtures read by compilation, vendor tests or provenance checks are declared inputs of those consumers. Exclusion from first-party formatting or claim policies remains exactly the existing vendor boundary; it is not exclusion from build accounting. An upstream-only artifact with no gate consumer may enter the explicit excluded list with its path, owner and reason. Changes to the vendored tree therefore remain visible without applying first-party rules to upstream material.

**Convention (Generated files)** · `conv:buildgraph:generated` Tracked datasets and rendered documents are declared outputs of their generators and inputs of fixed-point, document, correspondence or lint checks. They are excluded only from treatment as independently authored inputs, never from the tracked census or byte comparison. Declare the templates, source inputs and generator code that produce them. Preserve generate, write, clean-tree, check and repeat-check dependencies in the gate checkout; a developer's generation target is separate from a claim that committed outputs are current. Committed source-tree generations are effects named in the step report, not Meson output paths outside its build directory; the custom target publishes its report in the build root and records the exact generated source paths and byte comparisons. Untracked build artifacts stay in the build root and are accounted for by producer and consumer edges, not the tracked-source list.

**Convention (Harness dotfiles)** · `conv:buildgraph:harness` Tracked .linter declarations, claim registers, configuration and harness fixtures are declared inputs, even when their names begin with a dot. Untracked .lane reports, temporary service stores and build directories remain outside the tracked corpus under its existing ignore policy, because they are per-run products rather than source. Name their report and service-lifetime edges explicitly. A tracked harness metadata file with no execution consumer needs an individual purpose and exclusion; no blanket hidden-file exclusion is allowed. Private service credentials remain secret-owned under (`inv:observe:secret-boundary`), not copied into path lists or diagnostic reports.
