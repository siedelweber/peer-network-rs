**Record (Public API)** · `rec:api:decision` Status: accepted. Scope: GraphQL queries and types carried as CBOR, exact document bytes, execution bounds and public API evidence. Depends on: (`rec:interchange:decision`), (`rec:xchg:design-record`), (`rec:compatibility:decision`), (`rec:storage:decision`), (`rec:observe:decision`), (`rec:testing:decision`). ## Public API · `sec:api:record`

**Decision (Query and transport model)** · `dec:api:graphql` The public API uses GraphQL's query language, schema types, validation, field selection and execution model, with requests and responses represented directly in CBOR. A GraphQL document is source text inside the CBOR request, not a JSON document or a newly invented query syntax. Variables and results retain native byte strings and exact integers; no JSON conversion sits between transport and resolver. The query model gives callers typed selections over the public contracts, while CBOR preserves the values those contracts need. The API delivers existing domain operations and evidence; it creates no alternative formation, standing, title or admission law (`spec:design:implementation`).

**Decision (Encoding boundary)** · `dec:api:encoding-boundary` Request and response messages serve the caller that invoked the operation; their bytes have no document, act or command identity. Their CBOR reader admits the variations in (`rule:api:message-decoding`) and produces typed values before domain validation. This transport is explicitly outside the canonical-name language as repository adoption data in (`amend:interchange:api-messages`); it does not make noncanonical bytes members of (`lang:interchange:data-language`). Persistent or independently consumed binding documents remain canonical unsigned-key envelopes with namespace, version and assigned CDDL theory under records 008 to 010. Requiring every transient request spelling to be an identity would conflate a query's delivery with the act or publication it carries. Conversely, treating a canonical document as a repairable request would invalidate its byte contract. The two modes therefore have distinct entry points in pn-interchange: the strict document reader retains canonical-membership checks, while the bounded transport reader uses the same grammar walk and typed values without those checks (`amend:xchg:api-codecs`). One implementation keeps the number model, error vocabulary and resource accounting aligned; extending its walk is a smaller change than introducing another CBOR library. Neither mode selection nor re-encoding a transport value may substitute for strict validation of a canonical document's exact original bytes.

**Model (Request members)** · `model:api:request` One request is one CBOR map with text keys: query is required text containing the GraphQL source; operationName, when present, is text naming the selected operation; variables, when present, is a text-keyed map of variable names to typed CBOR values. Absence of variables means an empty variable map; a present null variables member is invalid. Absent variable values and explicit null remain distinct under GraphQL coercion and defaults. A document with several operations requires operationName. Reject unknown request members, duplicate keys and a top-level batch; an unsupported extension is not silently ignored. A mutation request selects one top-level field, counting aliases and fragments, so a transport batch never implies an atomic domain transaction. Schema validation and the selected operation's admission checks complete before any resolver side effect.

**Rule (Message decoding)** · `rule:api:message-decoding` Admit reordered map entries, legal wider integer and length heads, definite or indefinite arrays and maps, and definite or chunked byte and text strings. Reject duplicate decoded text keys at every map depth, malformed UTF-8 or chunk types, invalid breaks, reserved additional information, tags, unsupported simple values, non-finite floats, trailing items and truncated input. Every map in the request value model has text keys; field and variable names must also satisfy GraphQL's name rules where they serve that role. Use pn-interchange's planned transport-reading mode for API request and response messages only. Check explicit accumulated byte, item, depth and container/chunk nesting bounds in the shared grammar walk, including indefinite containers, before allocation or expansion can exceed a declared budget; count chunk headers and items as work even when they contribute no payload bytes. Retain grammar, value-validity and duplicate-key checks while omitting only canonical-membership checks. The API then applies its message and scalar restrictions to the same typed values as the strict reader. This does not add tags or other values to the API vocabulary. Join byte-string chunks without interpreting their contents; do not normalize text spelling or convert integer kinds through floating point. Equal decoded values use the same typed coercion and domain validation, irrespective of the accepted outer encoding. Actual received bytes still count toward transport limits and metering even when a shorter encoding would describe the same values.

**Convention (Scalar mapping)** · `conv:api:scalars` CBOR null, booleans, text, arrays and maps map to GraphQL null, Boolean, String, lists and input objects subject to the selected schema type. GraphQL Int retains its signed 32-bit range; exact counters and wider identities use explicitly declared custom scalars rather than widening Int by accident. The API's exact unsigned scalar accepts the full CBOR unsigned-integer range without a signed intermediate; exact byte scalars accept byte strings, not base64, hexadecimal text or arrays of integers. Byte-valued inputs use variables because GraphQL source has no byte-string literal. A finite CBOR float is admitted only for a schema Float position and never substitutes for an exact ledger value; integer-to-Float coercion follows GraphQL only at a Float position, without changing exact scalar paths. Large exact values, rationals and certified enclosures travel in their declared canonical document representation when the public scalar vocabulary does not express them. Custom scalar rules specify both variable and literal behavior; unsupported literal forms fail validation rather than round. Preserve response byte strings and unsigned values through the executor and writer as well as the reader.

**Model (Response members)** · `model:api:response` A response is one CBOR text-keyed map with data, errors and extensions governed by GraphQL's result rules. Successful fields appear under their response names, including aliases, with CBOR values matching the schema; list order is preserved, and field presentation follows query selection order without assigning identity to map order. Request parse or validation failure has errors and no data. Execution failure uses the prescribed null propagation and error paths, retaining only valid partial read results. Each error has its message and, where applicable, source locations and a path of text names and integer indices; extensions carries a declared failure class and request schema/resource edition. Domain verdicts are explicit typed result fields under (`rule:api:outcomes`), not inferred from errors being absent. A publication field is either its entire exact byte string or an error/null, never a truncated package. The writer emits definite containers and preferred heads for predictable output, but clients do not sign, compare or cache results by response-message bytes. This convention does not turn the response into a canonical interchange document.

**Invariant (Exact document carriage)** · `inv:api:document-bytes` The package of (`proto:design:encoding`), replay input documents and any other binding documents enter or leave the API as exact byte-string values. Transport decoding may remove byte-string chunk boundaries but changes no payload byte. The document consumer validates those original bytes with pn-interchange and the assigned theory; a noncanonical inner document is refused, never repaired by the transport. Publication signatures, equality and any declared identity recipe apply only to the designated document bytes, never to a GraphQL request, response or re-encoded selection of its fields. A query projection is a read result, not a substitute publication or proof of package completeness. pn-interchange emits canonical documents; the API message codec never replaces its encoder (`rec:xchg:concept-record`), (`spec:xchg:design`).

**Rule (Submission and retries)** · `rule:api:submission` Submission supplies a proposed act and its public authentication evidence through the records and host contracts. Decode, coerce, validate and authorize the typed proposal before deriving or checking its existing structural identifier; raw request bytes never supply that identity or an idempotency key. Whitespace, aliases, map order and admissible CBOR widths cannot turn the same act into a new act. Preserve any supplied signed document bytes through validation. The host durably records receipt and its outcome atomically under that act identity; an exact retry returns the recorded status, while conflicting bodies for one identifier are refused. Receipt, structural validity, final admission and publication are distinct states. A disconnect or deadline after a possible commit requires status recovery by act identity, not a claim of rollback or a second submission identity. Request arrival order is not authoritative act order (`inv:design:stable-references`).

**Decision (Schema authority and editions)** · `dec:api:schema` A reviewed schema description in GraphQL SDL and a data-backed operation/scalar/limit register define one API edition. The implementation gate compares parsed SDL, executable introspection, resolver coverage and that register; neither a generated schema nor introspection is its own independent oracle. Publish the description and register as canonical document content through pn-interchange, with assigned namespace and version theory before external use. The request endpoint selects an explicit API edition; it does not silently reinterpret a request against a different schema. Before 1.0, schema names, fields, scalars and supported editions may break freely and old editions need not remain served (`rule:compatibility:pre-one`). Assigned document theories still obey immutable assignments and the major-boundary law (`conv:compatibility:interchange`); transport/schema edition selection is not a waiver of those laws. This record creates no schema file or namespace assignment.

**Rule (Declared execution resources)** · `rule:api:limits` Each served edition declares finite ceilings and units for HTTP body bytes, GraphQL source bytes, decoded variable bytes/items, CBOR and input nesting, expanded selection depth, root selections, fields, aliases, fragment work, list/page sizes, resolver work, response bytes, concurrency and elapsed time. Count root fields at depth one, all field selections including introspection, and every repeated fragment occurrence before field merging; reject fragment cycles and bound the counting algorithm itself. Apply a published conservative cost rule using each field's declared work weight and bounded list multiplicity, with checked arithmetic; overflow or missing weights refuses execution. Coerced arguments and defaults determine list bounds, and runtime accounting checks actual work against the admitted estimate. Check both raw transport size and decoded work: alternative encodings may consume different transport resources but cannot change domain semantics. Limits and their counting rules are public declarations, not extra configuration files (`rule:storage:configuration`). Numerical budgets remain the separate deterministic inputs of (`req:design:limits`).

**Rule (Failure and cancellation)** · `rule:api:outcomes` Malformed encoding, invalid GraphQL and unsupported scalar/profile requests fail before resolvers run. Preflight resource excess reports unsupported with the named ceiling; runtime API exhaustion reports resource exhaustion and incomplete execution. Domain PASS, FAIL and INDECISIVE retain their evidence and meanings under (`sec:design:verdicts`); a timed-out request cannot manufacture FAIL or INDECISIVE for work that did not finish. Wall-clock deadlines cancel operational orchestration, never choose a binding answer or change the published refinement policy (`inv:observe:noninterference`). Read errors may yield GraphQL partial data with precise paths; no such result claims an atomic publication or complete replay input set. Mutation completion follows durable host state even when response delivery fails, as (`rule:api:submission`) requires. Client retryability and whether a durable outcome is known are explicit, separate from mathematical verdicts.

**Protocol (HTTP carriage)** · `proto:api:http` Serve one request and one response by HTTP POST over a deployment-provided HTTPS endpoint, using application/cbor for the body and response with the selected API edition fixed by the endpoint contract. Do not negotiate JSON as a fallback. Reject an unsupported content type with 415, an unsupported method with 405, an unacceptable response media type with 406, and an oversized body with 413. Other pre-execution request or validation refusals use 400; executed GraphQL responses use 200 even when fields carry errors, while inability to execute due to service unavailability uses 503. If a response cannot be delivered, no status code proves an operation did not commit. Return CBOR error bodies where a body can be produced. Bound body reading, decompression if enabled, execution, output buffering and connection work; prohibit a partial encoded response from being treated as a complete value. Subscriptions, incremental result delivery and websocket carriage are unsupported until separately decided. HTTP metadata carries no domain identity or verdict authority.

**Rule (Observation and claims)** · `rule:api:evidence` Instrument request decoding, validation, resource admission, each resolver, host transaction and response emission with their executing repository labels under (`rec:observe:decision`). Record full public requests, variables, results, errors and document bytes; metric attributes are bounded for cardinality, not content privacy. TLS keys, credentials, proxy details, private endpoint configuration and other instance material use (`dec:observe:secrets`) from acquisition through explicit access, including library errors (`inv:observe:secret-boundary`). Public API operations do not acquire a secret-management surface by implication. Mint claims at test sites with meaningful glosses under (`rec:testing:decision`); transport acceptance, executable GraphQL behavior and canonical-document acceptance require distinct evidence. Tests cover equivalent messages, scalar boundaries, exact inner bytes, malformed inputs, schema mismatch, resource limits, historical reads, retry/commit uncertainty and observation independence. No test-site claim is minted by this record.

**Proposal (Implementation dependencies)** · `proposal:api:dependencies` For owner review, use async-graphql for parsing, schema validation and execution, and hyper with tokio for HTTP service and asynchronous orchestration. The CBOR choice is settled: use pn-interchange for both bounded transport reading and canonical document handling, with its value model, number semantics, error vocabulary, encoder and bounds accounting; add no third-party CBOR dependency (`amend:api:shared-cbor`). The API adapter supplies message restrictions and response field presentation over those primitives. The remaining dependencies stay held until the implementation reviews versions, licences, feature sets, exact unsigned and byte-value paths, cancellation and secret-preserving errors. A serde or JSON convenience route that loses these properties is not admitted merely because the library offers it. Transport reading preserves keys until duplicate checks and enforces limits before materialization. Schema artifacts and publication-related documents still use the strict original-byte path; the transport entry point cannot establish canonical membership. No compatible dependency set or complete stock adapter is claimed here.

**Gate (Public API evidence)** · `gate:api:implementation` Before serving an edition, accept (`proposal:api:dependencies`) and (`proposal:design:api-placement`), assign the schema artifacts' document profile, publish finite limits with measured supported workloads, and execute independent CBOR and GraphQL cases through the actual server. Test both accepted message variations and rejected inner noncanonical documents, full unsigned boundaries and byte strings across inputs and outputs, fragment/alias/list cost attacks, missing and null variables, partial reads, exact package transfer, earlier-boundary results after later SCD2 changes, and mutation retries across commit/disconnect faults. Run the PostgreSQL cases on the real supported instance. Compare observation settings for identical completed binding bytes and verdicts; test secret carriers and full public content. The bidirectional claim query must link this gate and API contracts to their tests (`proposal:testing:gate`). Owner: the API implementer and repository reviewer; absent artifacts, dependencies or executions remain held under (`open:design:api-evidence`).

**Amendment (Development faucet)** · `amend:api:development-faucet` The development profile of (`rec:devnet:decision`) adds the faucet mutation and durable grant-status recovery under (`sig:devnet:faucet`). It uses the existing CBOR request, response, scalar, limit and failure contracts; it introduces neither another transport nor a domain verdict. Reject it in every other deployment profile at both resolver and host entry. Request identifiers scope operational retries to a declared chain run, never supply burn or act identity (`rule:devnet:grant-outcomes`). Its declared budgets complement (`rule:api:limits`), and its chain/database recovery evidence is required before service. Release support follows (`rule:compatibility:pre-one`).

**Amendment (Shared CBOR implementation)** · `amend:api:shared-cbor` The encoding boundary, message rule and dependency proposal now use pn-interchange for both modes (`dec:api:encoding-boundary`), (`rule:api:message-decoding`), (`proposal:api:dependencies`). This replaces the separate third-party message reader with a bounded extension of the existing grammar walk, so exact values, decoding errors and limits have one implementation. The strict canonical reader and its acceptance language remain unchanged. The mode and its independent claims land in (`gate:design:api-bites`); this decision is not evidence that the current library already accepts transport variations. Interface evolution follows (`rule:compatibility:pre-one`).

**Amendment (Node package and command entry)** · `amend:api:node-package` Name the network node library and executable pn. This replaces the provisional API-package name in (`proposal:design:api-placement`) without changing the public protocol or domain-crate boundaries. pn owns the schema, CBOR message adapter, service and bounded GraphQL execution entry point; pn-command depends on that library to operate the node and on pn-client for client workflows (`dec:harness:client-packages`). Start, inspect and administer use a separately declared, authenticated local control schema in the same CBOR-native GraphQL language, with the resource and outcome rules of this record. Local start dispatches through the library executor before the HTTP listener exists; the embedding entry point accepts and returns GraphQL message bytes, not a parallel per-operation Rust API. Public endpoints do not gain administrative authority, arbitrary RPC or secret-management fields by implication. Private control credentials and bootstrap context are secret-typed and passed outside public GraphQL variables, while all public operation content is traced. The command's JSON is presentation only. Node and client schema evidence includes shared scalars, unchanged node fields, exact document bytes and distinct client/control outcomes; editions follow (`rule:compatibility:pre-one`).
