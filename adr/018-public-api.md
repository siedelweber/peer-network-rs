The object has no timing or accounting members because (`rule:observe:metering`) already owns them. Driver faults and checked runtime failures are separate events: DriverFault carries the supplied observation instant and selects TransitionRefused, while RuntimeFailure carries that instant and selects the existing Configuration reason for failure of the controlled runtime or adapter, not StartFailed. Successful checked context construction makes the startup deadline available to inspection while still in Constructing, using checked addition of shell_start to the retained preparation instant; an unrepresentable sum is the existing Configuration construction refusal, not a missing timer. Startup remains active through Starting, ReadyCheck and Notifying, and is disarmed on retirement or on a clear successful notification completion into Ready. This exposes the existing cooperative bounds without adding an idle timer in Ready or changing the executor's execution deadline.

EndpointSetupFailed carries only the supplied observation instant and is admitted only in Constructing after successful checked context construction and before its Constructed completion; it selects NotificationFailed and enters Retiring at that instant, closing dispatch and notification and releasing owned setup resources with exit 1 and no success output.
