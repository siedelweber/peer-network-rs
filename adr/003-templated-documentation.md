## Templated documentation · `sec:render:record`

**Record (Templated documentation)** · `rec:render:decision` Status: accepted. Scope: TOML inputs, committed dataset projections, templates and rendered text. Depends on: (`rec:labels:decision`), (`rec:kinds:decision`). Does not establish: A current rendering establishes no correctness of the facts its input asserts.

**Setup (Context)** · `setup:render:context` A hand-maintained index can look current after the facts it repeats have changed.

**Decision (Policy)** · `dec:render:policy` Authored TOML inputs project into committed JSON datasets. A template at docs/templates/<path>.j2 renders only a permitted output at <path> under the same fixed-point gate: Markdown documents under docs/ and adr/, README.md, packages/documents/README.md, .linter/environments.toml, .linter/owners.toml, .linter/policies.toml, .linter/lists.toml and .linter/imports/paper.toml. The Markdown census still requires a template for every first-party Markdown document. Outputs under docs/inputs/, docs/datasets/, docs/templates/, docs/fragments/ or a vendored workspace member are protected; every output outside the allow-list is refused. Templates contain original prose and read repeated facts from those datasets. Both carriers begin with namespace and version in that order; malformed envelopes refuse before payload interpretation. Namespaces have the org.peer-network area and name shape, and versions are shortest-spelled nonnegative triples with supported major one. Payloads contain one rows array of objects; datetime and non-finite values refuse by field name because JSON has no matching value. The generator preserves row order and serializes object keys deterministically, ending with one newline. Repository release support follows (`rule:compatibility:pre-one`).

**Consequence (Tradeoffs)** · `cor:render:tradeoffs` The documents library owns both carriers. Minijinja stays on major three with its default features and serde support enabled. Variable, block and comment delimiters are the standard {{ }}, {% %} and {# #}; literal doubled braces use raw blocks. Files under docs/fragments/ are loaded under their fragments/ names for include and import, outside the output template tree, and produce no independent output. Undefined values fail and autoescape is disabled. The row function requires exactly one matching row, rows preserves file order, require rejects a false premise with its message, number formats numeric values without deriving facts, exhibit replaces complete parenthesized supplied labels with doubled-delimiter exhibitions without changing their source prose, and length counts a collection only to serve a premise inside require. The kinds_registry function reads the kinds dataset and computes its catalogue counts, ordered effective pairs and homonyms in the engine; templates only present those views and the input rows. The toml_string filter quotes a string as a TOML declaration value, and split projects string segments by a supplied separator only for presentation or a require premise, not to infer new facts. Templates compute no facts; review enforces this restriction because the engine retains its operators. Every data-dependent assertion states its premise through `require`. The dependency census records reads observed during rendering, not reads in branches that did not execute. A literal template reproduces its bytes. generate updates datasets; generate --check and check write nothing; write refreshes documents but still reports changed files as findings. `census` reports templates, datasets, output documents, unrendered templates and datasets no executed template reads. `check` pairs record templates with index rows and requires a template for every first-party Markdown file. The extra committed files cost review space but make changes reproducible without a network.

**Gate (Verification)** · `gate:render:verification` The gate runs generation and document writes, requires a clean working tree, then checks the results; repeating the read-only checks witnesses determinism. The Markdown census reads tracked paths through Git and refuses if Git is unavailable; untracked notes do not enter it. Vendored crate paths come from explicit, normalized workspace member paths under `vendor/`, and only those paths are exempt. A record must read its index row using its own document path. Tests mutate datasets and renderings, reject envelope defects and missing rows, exercise premises and verify literal templates. A clean tree must be a fixed point.

**Amendment (Release support)** · `amend:render:pre-one-003` The dataset major and supported command surface in (`dec:render:policy`) describe current admission, not compatibility with earlier repository states. Dataset and template changes follow (`rule:compatibility:pre-one`); regenerate current outputs rather than provide a cross-version migration.

**Amendment (Numeric registry)** · `amend:render:numeric-registry` Repeated numeric facts belong to one committed input, docs/inputs/numbers.toml, projected to org.peer-network.numbers.registry. An id names one quantity; equal values in different roles take different descriptive ids. Structural small integers remain literal and have no registry entry. Each row declares a label-shaped id, a full-precision exact value string, a unit from Work, bytes, seconds and dimensionless, and a display rule. Values are signed decimal integers, rationals with positive integer denominators, or finite exact decimals; neither binary floating-point approximations nor scientific notation enter this carrier. An exact rule requires its digit budget to admit the whole value. A rounded rule declares a signed decimal exponent: magnitude m rounds to a multiple of ten to the power m, nearest with half ties away from zero. Floor and ceiling rules use the same magnitude and round toward negative and positive infinity respectively. Lower enclosure endpoints use floor; upper endpoints and certified upper bounds use ceiling, so a display cannot narrow the certified enclosure. Derived display ranges use the same outward endpoint rules; this does not turn a timing projection into a runtime guarantee. The exact form is emitted only when its digit count, excluding signs and separators, fits exact_digits. The input projection computes both forms, their exactness flags and relation symbols with integer arithmetic, before rendering; the renderer performs no rounding or arithmetic on these facts.

**Convention (Numeric displays)** · `conv:render:numeric-displays` The numval accessor selects a bare form by id, defaulting to num; its optional exact argument requests the budgeted exact form. The numrel accessor selects the same form and selects the generated relation: = for equality with the exact value, ≈ for nearest rounding, ≥ for an inexact floor and ≤ for an inexact ceiling. The relation reads from the exact quantity to its displayed value; place it between complete expressions. Unknown ids, unknown forms, missing exactness, missing or inconsistent relations and omitted exact forms refuse rendering. Decimal points remain dots. Narrow nonbreaking spaces group integer digits from the right and fractional digits from the left in threes, independently on each side of a rational slash. Groups aid comparison, avoid comma ambiguity with decimal separators and lists, render directly in Markdown without HTML, and interrupt long identity-shaped digit runs. Nonbreaking spacing keeps a displayed quantity together. Displays are not normative: the defining formula, certified enclosure or pinned exact value remains authoritative, as in network-v0.31.1, ``ver:standing:conserved-equilibrium-enclosure``. A value the code reads and the record displays keeps one authority, so the two cannot drift. A value that a definition or theorem fixes stays literal even where code reads it, such as the anchor rung 0, full strength 1 or a theorem’s zero. Its authority is the definition; a registry entry would present it as a figure that could change. Subject to this precedence, a number cites a quantity id when code reads it as a value: a fixture’s declared input, including its depths and masses, or a measured output. A number stays a word when it names a structure whose size the definition fixes, or forms a compound, idiom or name, such as two-map, four-Actor or precision-four. Structural integers in formulas, indices, encodings, version identities and bite identifiers may remain literal, including N − 1, x = 1 and a fixture named wall 2. Grouping is projection output; a template must not type U+202F outside a template expression. A rendered-text control on the migrated implementation document rejects digits joined to number-word fragments or these word compounds; units attached to measured quantities remain valid. Published figures stay together in the registry under quantity ids, and their corpus comparisons read every figure through NumberId: keeping full-precision transcriptions beside their displays prevents split authority. An upstream default relied on by code or prose has a quantity id naming the upstream owner, so a changed default cannot silently change an unrelated limit. Limits defined by our encoding specification are structural and stay literal, as do identities such as digests. A recorded elapsed-time decimal is exact as a recorded sample, not a claim of exact physical duration.

**Gate (Numeric correspondence)** · `gate:render:numeric-correspondence` Tests select generated NumberId variants and load their exact values directly from the same committed input. The generated accessor contains ids and checked source spans, never a second numeric pin; removing an id removes its variant. The fixed-point gate regenerates the accessor together with the dataset, binding test pins and displays by construction. General registry entries carry no provenance, source label, kind or build statement: the consuming code and its claims explain where a value comes from. Published act result entries additionally carry their exact paper key and tag under (`rule:design:published-act-correspondence`), allowing a supplied external value registry to be checked without copying its contents into the tree. The hash-citation family's numeric-registry reader admits only validated exact-value field spans in the input and projected dataset at their two exact paths. This identifies long digit runs as numeric data without weakening identity accounting in other fields, prose, code or tests. Malformed numeric fields refuse even when they contain no identity-shaped run. Witnesses cover field-local admission, template and non-value refusal, unknown ids, omitted forms, generated relations, grouping, nearest and directed rounding for positive and negative rationals, number-word fragment refusals, typed pins and repeated fixed points.

**Rule (Rendered spacing import base)** · `rule:render:spacing-import-base` The rendered Markdown cleanup list and both per-path debt ceilings may only shrink against the import base supplied by PN_IMPORT_BASE. The checker resolves that commit and requires it to be an ancestor of the checked head; an invalid supplied base refuses. Only an absent interface falls back to HEAD^ for standalone checks. A final-head gate therefore still sees debt introduced by an earlier commit of the same slice. Missing paths and resolved exemptions retain their per-path refusals.
