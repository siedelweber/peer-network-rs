## Toolchain and build profile · `sec:toolchain:record`

**Decision (Compiler)** · `dec:toolchain:compiler` The workspace tracks the undated nightly channel with rustfmt and clippy. Every workspace build, test and gate runs on compute nodes whose shared toolchain root carries the current nightly; worker accounts cannot install a toolchain there. The toolchain file therefore names the channel the nodes carry rather than a date they may not carry. Since no pin records the compiler, the gate log is the record of the versions that checked each commit.

**Decision (Minimum compiler)** · `dec:toolchain:minimum` The workspace and its first-party members declare no minimum compiler version. Tracking nightly would make a minimum a claim nothing checks, and no downstream consumer builds this workspace on an older compiler.

**Decision (Release profile)** · `dec:toolchain:release` Releases use thin LTO and 1 codegen unit. Thin LTO provides most of full LTO's cross-crate inlining at a fraction of its link time, and one codegen unit lets the optimiser see each crate whole. Dev and test profiles retain Cargo defaults so gate builds keep their incremental speed; changing their optimisation levels requires later measurement.

**Gate (Verification)** · `gate:toolchain:verification` The toolchain step requires the exactly undated nightly channel, both declared components and answering compiler, Cargo, Clippy and formatter commands, and logs rustc -vV, cargo -V, cargo clippy -V and rustfmt -V. The build-policy step refuses minimum compiler declarations in the workspace and first-party members, requires the release profile, and refuses dev or test overrides. The discipline-tests step witnesses rejection of dated nightly, stable releases and missing components.

**Amendment (Development performance measurements)** · `amend:toolchain:development-performance` The current defaults and refusal of dev/test overrides remain the implemented policy until the foundation bite of (`gate:devperf:foundation`). That bite measures and decides the dev/test settings under (`dec:devperf:profiles`), then updates the profile declarations, checker and witnesses together to enforce the reviewed choices. This refines (`dec:toolchain:release`) and (`gate:toolchain:verification`) without changing nightly tracking or the release profile. Build-time excess is a warning and an owned misconfiguration finding, never a failing gate verdict (`rule:devperf:builds`), (`rule:devperf:nonverdict`).

**Amendment (Measured gate profile)** · `amend:toolchain:measured-gate-profile` This settles (`amend:toolchain:development-performance`) and refines (`dec:toolchain:release`) and (`gate:toolchain:verification`) through the measured choice in (`amend:devperf:measured-choices`). Adopt a named gate profile inheriting dev with optimization level 1, debug information 0, debug assertions true and overflow checks true. Ordinary dev and test retain their debugging defaults, and release is unchanged. In the one-setting-at-a-time campaign, median warm test times were 6.987 seconds at optimization 0/debug 2, 7.573 seconds at optimization 0/debug 0 with variable contention, and 4.571 seconds at optimization 1/debug 0; median document checks were 0.678, 0.603 and 0.357 seconds. Cold test builds were 15.198, 15.366 and 23.529 seconds. Removing debug information alone is not claimed to speed test execution. The chosen gate profile trades a bounded cold cost and gate-only symbols for recurring execution and link savings; debugging remains available through the unchanged dev/test profiles. The independent profile campaign measured comment-only documents rebuild medians of 0.627 seconds before and 0.475 seconds after; this measures front-end and relink cost, not a changed implementation workload. The build-policy checker requires exactly the reviewed release and gate profiles and continues to refuse dev/test overrides. Its witnesses reject changed optimization or symbols and disabled debug assertions or overflow checks. Gate Clippy, test, documentation and document-engine commands select the same named profile; timing findings remain separate from their semantic status.
