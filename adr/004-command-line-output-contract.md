## Command-line output contract · `sec:output:record`

**Record (Command-line output contract)** · `rec:output:decision` Status: accepted. Scope: First-party command-line results, controls, diagnostics and exit classes. Depends on: (`rec:labels:decision`). Does not establish: Command-line streams establish no externally consumed interchange format.

**Setup (Context)** · `setup:output:context` Automation cannot reliably consume a stream that mixes result data with diagnostics or human help.

**Decision (Policy)** · `dec:output:policy` The implemented baseline uses cli-common for argument parsing, panic hooks and tracing, with a terminal-stdout usage refusal; the decided replacement below has no such refusal. Successful result output is one JSON object followed by a newline; diagnostics, help, version, usage errors and panic reports use JSON stderr. Help and version return zero with empty stdout. Usage and terminal refusal return two. Runtime failure returns one and leaves stdout empty. Document findings return three, including files refreshed by write. The process wrapper may relay child bytes as its explicit result contract. The observation-by-build-kind common boundary and its consumers are implemented; separately compiled recipe evidence is implemented through registered package-scoped artifacts and their focused controls; installation remains owed. What a command is asked for, including an answer or a diagnostic report, is its result on stdout; stderr records how the command went about its work. Help and version are result requests: their existing JSON record shapes, with a version build_kind member naming release or debug, are written as one JSON object followed by LF to stdout with status zero in every admitted observation mode and build kind. Neither observation disable nor level filters those results. The designed output policy admits terminal stdout for every command; terminal attachment is not a refusal or a cause of status two. Stdout carries only a whole result from a command ending with status zero, never a result stream or a partial result; a command ending nonzero delivers nothing there and reports its error through the selected stderr observation policy. The result is serialized completely before its one stdout write attempt; a failed operating-system write can still leave a physical prefix, so physical rollback is not claimed. The implemented documents surface has generate check and generate write for datasets, and render check and render write for documents. A check mode writes no datasets or documents; without --output=report it returns zero when clean or three with differences, with empty stdout in either case. Its enabled terminal error carries only the finding count and the fixed hint rerun this command with --output=report, not finding text, paths or a report fragment; validly quiet release leaves the status alone. This fixed detail shape avoids a second report channel or an arbitrary selection of findings and remains subject to the existing observation record-capacity and delivery rules. A completed write mode returns zero whether or not files changed. The closed set of --output values is report; any other value is a usage error. On either base and mode, --output=report requests the whole operation report as one JSON stdout result with exit zero on completed evaluation or writing, differences or changes included; without the option these operations write no stdout report. For each check mode, the option and its absence share one read-only evaluator, root and inputs by construction; only the result route and differences exit differ. A write report retains the operation's complete report, identifying refreshed files by the existing stale-dataset or stale-document finding kinds, and retaining orphan-dataset or unrendered-template findings without implying those files were changed; it includes the empty change set when nothing differed and is returned only after all writes complete; inability to complete is a runtime error, with empty stdout, not a successful report. The option does not suppress native results: census returns its listing with zero even without --output, and installation-check retains its separately decided result and exit under (`amend:design:test-installation`); --output=report changes neither command's result nor its exit. Explicit report-file and success-stamp roles are spelled --report-file and --stamp-file, retain their reciprocal admission, compare-if-changed report publication and clean-only stamp rules, and keep stdout empty. Where accepted, that pair conflicts with --output=report rather than selecting two result sinks. Those roles remain separate from dataset/document mutation; a check mode may publish an explicitly requested report asset but never refresh its checked files. A report request does not turn differences into a clean stamp premise. The spellings --report and --stamp, bare generate, generate --check, plain check and plain write have no compatibility aliases under (`rule:compatibility:pre-one`). The implemented command spellings and status-three stdout reports, including write's refresh status, remain baseline evidence until these replacements are built. Bad or conflicting observation selection remains a pre-work usage refusal, not an admitted mode in which help or version ran. Usage errors, refusals and panic diagnostics are not expected results and remain observation on stderr, subject to the designed mode. Other successful result contents and exit classes are unchanged; terminal attachment no longer selects usage. The initial policy sentences describe the historical baseline; the shared replacement above is implemented for the common boundary and consumers, including the documents modes, report option and file-role spellings; separately compiled recipe artifact controls are implemented through registered package-scoped artifacts and their focused controls; installation remains owed.

**Consequence (Tradeoffs)** · `cor:output:tradeoffs` The `documents-panic-probe` binary exists only to exercise the same panic-hook installation function as the real command in a piped subprocess; its conventional integration test owns the claim and test labels. Commands return ExitCode, and controlled emission belongs to the shared crate. Usage errors omit argument values. Panic payloads remain hidden until parsed debug mode enables detail; classified secrets and raw child arguments are never diagnostic fields. Tracing prefers a nonempty RUST_LOG, then debug, then the command default. Automatic terminal pretty-printing and command-specific reinterpretations of the reserved statuses are rejected because callers need stable branches. Repository release support follows (`rule:compatibility:pre-one`).

**Gate (Verification)** · `gate:output:verification` Subprocess tests verify JSON help, version and usage failures, terminal refusal before mutation, and a panic with empty stdout and one JSON diagnostic. Clippy denies uncontrolled printing and process termination. These claims describe the implemented output contract. The decided replacement under (`dec:output:policy`) requires separate stdout help/version and quiet-stderr controls before its implementation is claimed; a current one-JSON-panic claim remains evidence for its enabled configuration, not for absence of output. For the implemented surface, the documents integration controls are document_modes_cover_current_check (the union of generate check and render check detects every current check finding and census refusal, with dataset, document, orphan, unrendered-template and census neighbours), check_findings_observation (both check modes without the report option give three, empty stdout and only count plus fixed report-option hint for differences, with clean and quiet-release neighbours), operation_report_result (the report option returns each mode's whole report with zero on completion, including dirty checks and changed or unchanged writes, while incomplete operations remain errors), and document_surface_selection (only the decided command and output spellings are admitted, with census and installation native results and invalid-value neighbours). The common integration control checker_file_role_spellings witnesses the renamed reciprocal pair and unchanged report/stamp publication predicates, including a dirty report request that cannot create a clean stamp and the conflicting stdout report request. Each owns that single claim at its package's integration site and runs with cargo test --offline --locked --profile gate -p PACKAGE --test integration NAME -- --exact, substituting documents or cli-common and its selected name. These controls cover the changed boundaries; broader failure campaigns remain with the existing publication and observation evidence owners. The earlier finding-status claim is retired in favor of the mode controls; compiled-kind recipe evidence retains its separate owner and implementation cut.

**Amendment (Test harness protocol)** · `amend:output:test-harness-protocol` The harness-free wallet allocation test implements nextest's discovery protocol in place of libtest: its private list_case boundary writes only the fixed decoder_reservations test inventory line to stdout, outside every measured allocation window; ignored-only discovery writes nothing. This test-only protocol is an exception to the JSON result rule in (`dec:output:policy`), not a command output mode. Other printing, stream access and process termination remain forbidden, including inside the boundary. The output-discipline witness checks the boundary's path and item scope, and nextest discovery and execution verify its protocol.

**Amendment (Release support)** · `amend:output:pre-one-004` The stable branches in (`cor:output:tradeoffs`) are the current command contract. Across pre-1.0 repository releases, commands and their JSON surfaces follow (`rule:compatibility:pre-one`); this record creates no deprecation or migration path.

**Amendment (Labelled observation)** · `amend:output:observability` The JSON tracing initialized under (`dec:output:policy`) carries the labelled operation, metering and metric-summary contract of (`rec:observe:decision`). It remains on stderr; result stdout, exit classes, filter precedence and secret-type protection remain the command contract. Bootstrap and early help/refusal paths need the bounded observation treatment in (`proposal:observe:enforcement`); the current initializer alone establishes no complete instrumentation claim. Trace and metric names follow (`rule:compatibility:pre-one`).

**Amendment (Full observation)** · `amend:output:full-content` For observation, (`amend:observe:full-content`) supersedes the argument-value omissions, hidden panic payloads and raw-child-argument exclusions of (`cor:output:tradeoffs`), and the former text-redaction clause of (`amend:output:observability`). Record public arguments, panic payloads, child arguments, results and errors in full under (`rule:observe:privacy`); instance-private material exists only in the secret carriers of (`dec:observe:secrets`) and is observed as its role and redaction marker. Filtering public values cannot explain an operation completely, while secret typing protects private values at every observation boundary. JSON stdout/stderr separation, result counts, exit classes and level/sampling policy remain unchanged; content completeness does not require delivery of every event. The foundation bite must establish the secret boundary before enabling integrations, including child processes, under (`inv:observe:secret-boundary`).

**Amendment (Public-content implementation)** · `amend:output:public-content-core` This implements the supersession in (`amend:output:full-content`): cli-common parser diagnostics retain the complete public clap text and the original argv bytes, including values abbreviated by clap; string panic payloads are no longer conditional on debug; text and field-name redaction helpers are removed; and runner errors retain their public Display text. Execwrap records its public command before spawn, successful and failed results, and child I/O bytes without rewriting the bytes sent to the selected result sinks. Private instance values must arrive through secret-owned acquisition and admitted consumers; an ordinary command argument, including a URL-shaped fixture, is public input rather than a secret carrier. The executable-owned bootstrap composes the accounting layer and metrics recorder and sends JSON observations to stderr, leaving stdout and exit predicates unchanged. Rust supplies no Debug access to an arbitrary non-string panic payload, so that unavailable representation is not invented. Complete instrumentation and secret-consumer admission remain at (`gate:observe:foundation`).

**Amendment (One emission setting)** · `amend:output:emission-setting` The debug flag in (`cor:output:tradeoffs`) remains accepted, with help stating that it does not select observation level; PN_OBSERVE_LEVEL is the sole emission route under (`amend:observe:emission-levels`). The inert execwrap quiet flag is removed. Full public payload capture is available only at trace; diagnostics and accounting retain the default contract. The implemented common boundary separates observation enablement from level: PN_OBSERVE_DISABLE=1 alone requests disable, while PN_OBSERVE_LEVEL selects error, default or trace under (`amend:observe:emission-levels`). Help and version results are outside both inputs under (`dec:output:policy`). The sole-emission wording describes the historical baseline; the separate disable input and three levels are implemented in the common boundary.

**Amendment (Emission precedence supersession)** · `amend:output:precedence-supersession` Supersedes by name the RUST_LOG-then-debug-then-default tracing clause of (`cor:output:tradeoffs`) and the retained filter-precedence clause of (`amend:output:observability`). Under (`amend:output:emission-setting`), PN_OBSERVE_LEVEL alone selects default or trace. The cli-common debug flag does not select a level. Execwrap's debug flag additionally requests Writer write and typeset-line debug events, which are captured only when trace is selected; its flag cannot enable persistence at default. These events describe public bytes and lines and do not rewrite the relayed output. In the implemented common boundary, the same level selector admits error as well as default and trace, and the separate disable input and its conflict rule govern observation enablement. The shared debug argument remains inert for this selection. Execwrap is a workspace tool, not a shipped executable: its legacy collection option remains a tool input rather than a shipped disable alias, and child-stream relay and result mapping are unchanged.
