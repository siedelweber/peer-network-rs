## Command-line output contract · `sec:output:record`

**Record (Command-line output contract)** · `rec:output:decision` Status: accepted. Scope: First-party command-line results, controls, diagnostics and exit classes. Depends on: (`rec:labels:decision`). Does not establish: Command-line streams establish no externally consumed interchange format.

**Setup (Context)** · `setup:output:context` Automation cannot reliably consume a stream that mixes result data with diagnostics or human help.

**Decision (Policy)** · `dec:output:policy` First-party executables use cli-common to parse arguments, install the JSON panic hook before startup, initialize JSON tracing and refuse terminal stdout before work. Successful result output is one JSON object followed by a newline; diagnostics, help, version, usage errors and panic reports use JSON stderr. Help and version return zero with empty stdout. Usage and terminal refusal return two. Runtime failure returns one and leaves stdout empty. Document findings return three, including files refreshed by write. The process wrapper may relay child bytes as its explicit result contract.

**Consequence (Tradeoffs)** · `cor:output:tradeoffs` The `documents-panic-probe` binary exists only to exercise the same panic-hook installation function as the real command in a piped subprocess; its conventional integration test owns the claim and test labels. Commands return ExitCode, and controlled emission belongs to the shared crate. Usage errors omit argument values. Panic payloads remain hidden until parsed debug mode enables detail; classified secrets and raw child arguments are never diagnostic fields. Tracing prefers a nonempty RUST_LOG, then debug, then the command default. Automatic terminal pretty-printing and command-specific reinterpretations of the reserved statuses are rejected because callers need stable branches. Repository release support follows (`rule:compatibility:pre-one`).

**Gate (Verification)** · `gate:output:verification` Subprocess tests verify JSON help, version and usage failures, terminal refusal before mutation, and a panic with empty stdout and one JSON diagnostic. Clippy denies uncontrolled printing and process termination.

**Amendment (Release support)** · `amend:output:pre-one-004` The stable branches in (`cor:output:tradeoffs`) are the current command contract. Across pre-1.0 repository releases, commands and their JSON surfaces follow (`rule:compatibility:pre-one`); this record creates no deprecation or migration path.

**Amendment (Labelled observation)** · `amend:output:observability` The JSON tracing initialized under (`dec:output:policy`) carries the labelled operation, metering and metric-summary contract of (`rec:observe:decision`). It remains on stderr; result stdout, exit classes, filter precedence and secret-type protection remain the command contract. Bootstrap and early help/refusal paths need the bounded observation treatment in (`proposal:observe:enforcement`); the current initializer alone establishes no complete instrumentation claim. Trace and metric names follow (`rule:compatibility:pre-one`).

**Amendment (Full observation)** · `amend:output:full-content` For observation, (`amend:observe:full-content`) supersedes the argument-value omissions, hidden panic payloads and raw-child-argument exclusions of (`cor:output:tradeoffs`), and the former text-redaction clause of (`amend:output:observability`). Record public arguments, panic payloads, child arguments, results and errors in full under (`rule:observe:privacy`); instance-private material exists only in the secret carriers of (`dec:observe:secrets`) and is observed as its role and redaction marker. Filtering public values cannot explain an operation completely, while secret typing protects private values at every observation boundary. JSON stdout/stderr separation, result counts, exit classes and level/sampling policy remain unchanged; content completeness does not require delivery of every event. The foundation bite must establish the secret boundary before enabling integrations, including child processes, under (`inv:observe:secret-boundary`).
