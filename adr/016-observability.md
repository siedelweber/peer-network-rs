## Observability · `sec:observe:record`

**Decision (Foundation)** · `dec:observe:foundation` Observability precedes the first domain crate. Every operation that does work executes within a tracing span; every span and event identifies the repository claim, contract or algorithm it executes. Every operation has work, resource and elapsed-time accounting and declared metrics, including refusal and incomplete execution. Introducing these obligations before implementation makes coverage reviewable at each new contract rather than leaving unobservable paths to retrofit. An operation's trace explains which labelled work ran; it does not prove that work correct (`cav:labels:non-normativity`).

**Rule (Operation boundaries)** · `rule:observe:spans` Each public function body and named design operation has an operation span, with nested spans for independently accountable stages. Private helpers execute within the caller's span unless they establish a separate work or resource boundary, in which case they have their own. Propagate context across asynchronous suspension, spawned tasks and worker threads; instrument a future through its execution rather than retaining an entered guard across an await. Cancellation, error, panic unwinding and normal return close accounting with distinct outcomes; abrupt process loss leaves an incomplete operation, never a fabricated completion. Libraries emit instrumentation without installing global subscribers; the executable owns initialization and export. Bootstrap and instrumentation machinery require the narrow exceptions in (`proposal:observe:enforcement`), not an unlabelled escape from the discipline.

**Convention (Names and fields)** · `conv:observe:names` The static span or event name is its primary repository label text, with explicit claim_owner and claim_label fields; execution_owner identifies the emitting crate's owner. An operation field distinguishes operations of one contract, and an event_kind field distinguishes start, progress and completion. Each event carries these fields even if its parent span was filtered out. A formation span names (`alg:design:formation`), for example. Runtime strings are data, not fresh mints or a new synthetic-citation class: a checked source mapping pairs each constant with an ordinary resolving citation, including the declared owner import where needed (`inf:labels:synthetic-citation`). The checker validates that pairing; binding code never loads the label graph. Metric stems encode lowercase execution owner, claim owner, kind, area and name with double underscores between components and single underscores replacing name hyphens, followed by a double underscore and the declared measure/unit suffix; the restricted label alphabet makes the component encoding reversible. The gate rejects duplicate exported names, including exporter normalization collisions. Trace fields use fixed snake_case names with declared types and units, never user-supplied keys. These names may change freely before 1.0 under (`rule:compatibility:pre-one`).

**Rule (Metering)** · `rule:observe:metering` An operation records monotonic elapsed wall time from entry to terminal outcome, including waits, in seconds; task suspension is included. Work is counted in declared units such as acts, edges, iterations, bytes or queries; account retries and refused attempts explicitly. Resource accounting distinguishes current usage, high-water usage and cumulative traffic, and declares whether a measure is exact, estimated or unavailable. Never substitute zero for an unavailable CPU or allocation measure. Parent durations are inclusive and are not summed as disjoint work; each work increment has one owning operation, and any aggregate states its roll-up rule. A completion record carries duration, outcome and totals; incomplete records carry known partial totals. This becomes the uniform wall-time evidence for actions and child-process execution, replacing independent script timers only after the foundation gate proves coverage. Existing gate wall reporting remains until then. Gate resource samples keep process accounting, sampled cgroup accounting and system-wide kernel observations separate. Read the unified hierarchy mount, the sampler’s own cgroup path and namespace init’s path. A sampled hierarchy mounted at its root with both processes at that root is labelled namespace-root-cgroup, as on the supported container route; other readable hierarchies are labelled shared-or-unproven-cgroup, without asserting another workload is present. Missing hierarchy evidence remains hierarchy-unavailable-cgroup. Retain recursive cgroup.procs membership and readable member paths separately as snapshot evidence. A process exiting during that enumeration makes membership unavailable, not the stable hierarchy identity; it must not change the node comparison key. These labels establish neither exclusive gate ownership nor uninterrupted membership between samples. No cgroup is called the gate’s own solely because it is sampled. Its usage and pressure never stand for node-wide activity. At each gate and step boundary, retain system-wide /proc/pressure/cpu, memory and io counters, /proc/stat CPU ticks and boot time, and the first three /proc/loadavg averages beside the cgroup samples. The proc readings are labelled node-wide with source proc-systemwide only when the sampled proc path is a procfs mount and none of pressure, stat or loadavg is shadowed by a subordinate mount; absent provenance leaves the source unavailable. The node identity records the observed source and cgroup scope, rather than fixed scope strings. On Linux the kernel’s procfs PSI totals and aggregate CPU ticks have system-wide scope; the loadavg task counts and namespace-local last process id are not node-load evidence. A bracketed host/container comparison establishes this visibility on the supported worker without generating competing load. Node busy cores divide the busy tick delta by the kernel clock tick rate and elapsed wall; guest ticks already included in user ticks are not added again. PSI fractions divide cumulative stall deltas by elapsed wall, never differences of rolling averages. Missing readings, backwards counters or a changed boot leave the affected node observation unavailable. Cgroup deltas remain named cgroup deltas, with no fallback into node figures; process-and-child CPU remains the gate's own accounting. Overlapping intervals are context and cannot be summed as disjoint resource use.

**Convention (Metrics)** · `conv:observe:metrics` Every operation exposes counters for started and completed operations and work units, a gauge for active operations and declared live resources, and histograms for elapsed seconds and workload sizes. Completed counters distinguish bounded outcomes, including cancellation and observation loss where applicable; process death may leave starts unmatched. Decrement active gauges on all orderly exits. Each metric declaration gives its owning label, measure, counter/gauge/histogram kind, unit, aggregation rule and finite attribute vocabulary; histogram boundaries are reviewed operational settings. Metric attributes contain only bounded categories such as outcome, operation or refusal class. Never use an act identifier, epoch, address, request identifier, raw label supplied by a caller or error text as a metric attribute. Counts of work are observations of performed work, not counts of proven claims. Names follow (`conv:observe:names`) and (`rule:compatibility:pre-one`).

**Decision (Sinks and ownership)** · `dec:observe:sinks` Executables send traces, completion metering and metric summaries as JSON to stderr under (`rec:output:decision`); stdout remains the command's result stream. Long-running services additionally export traces and metrics through bounded queues with explicit loss accounting. The application composes the subscriber and recorder once; reusable libraries neither replace them nor initiate exporters. Operational service export settings belong in the database under (`rule:storage:configuration`), not an additional configuration file; connection-only bootstrap uses local stderr before those settings are available. Emission follows (`amend:observe:emission-levels`); legacy verbosity arguments do not silently enable payload persistence. Private export endpoints and authentication material are secret-typed and observed as role and redaction marker under (`rule:observe:privacy`); all public content is recorded in full. Export loss, queue saturation or a disconnected sink cannot block or fail binding computation; reporting uses reserved bounded resources, and lost observations remain disclosed as loss rather than silently interpreted as zero work.

**Proposal (Collection and export)** · `proposal:observe:export` Accepted with implementation conditions: retain tracing and tracing-subscriber for spans and JSON, add a reviewed tracing-subscriber layer for operation accounting, use the metrics API for declared counters, gauges and histograms, and use tracing-opentelemetry with opentelemetry, opentelemetry_sdk and opentelemetry-otlp for service trace export. A single application-owned metrics recorder would forward the same declared instruments to the SDK's metric provider, with a JSON snapshot sink for executable summaries. This separates library instrumentation from deployment transport and avoids two independently counted metric systems. These collection and export roles are accepted, not claims that an off-the-shelf recorder or compatible version set has been established. The separate secrecy library choice is decided in (`dec:observe:secrets`); its integration is part of the same foundation bite. The foundation implementer must review APIs, licences, versions, feature sets, bounded queue behavior, metric translation, shutdown and secret-preserving dependency boundaries; the reviewer admits the demonstrated integration before dependencies are added. Exporter construction remains outside domain crates. A local recorder must work without a collector; failed export cannot hold a mathematical result hostage. Trace and metric surface evolution follows (`rule:compatibility:pre-one`). The foundation bite must name and review the bridge from the metrics recorder to the OpenTelemetry metric provider, prove a compatible version set and retain exporter credentials in the secret type throughout the integration. Acceptance of the roles does not establish that evidence.

**Rule (Levels and sampling)** · `rule:observe:sampling` Use INFO for operation lifecycle and bounded outcomes, WARN for degraded observation or operational conditions, ERROR for operational failure, DEBUG for diagnostic stages and TRACE for detailed progress. A mathematical FAIL or INDECISIVE is a typed completed verdict, not automatically an ERROR. Filter or sample detailed trace delivery by declared operational policy; record the policy and dropped-record totals so sampled absence is not evidence of no work. Accounting and metric updates run independently of trace filtering and sampling and do not extrapolate exact totals from sampled spans. If collection itself is disabled or unavailable, mark the observation unavailable. The design of operation contexts must therefore not rely on a subscriber receiving a filtered span. Deterministic work-budget accounting continues regardless of all observation settings (`inv:observe:noninterference`).

**Rule (Full observation and secret types)** · `rule:observe:privacy` Operations are instrumented to record their arguments, results, SQL parameters, errors including unsanitized driver errors, and Debug representations in full when full tracing is selected under (`amend:observe:emission-levels`). There is no content allowlist, argument skipping, payload suppression or sanitization step. Acts, records, ledgers, declarations, standing and publications are public network data; personal data in those public inputs is not a separate reason to withhold it. Full content explains what an operation did, while a hand-maintained filtering list drifts as fields and error paths change. At trace level a bounded operation formats its whole supplied input before its bound refuses it, a nested decoder formats content before an enclosing operation refuses, and a store read formats the whole store. Trace level is for exceptional debugging and is never the default: only a run requesting it bears this cost. Captured output is bounded by the capture limit, not by each operation's bound; that limit does not bound the work of formatting the input. Recording lengths before admission instead is set aside because network data is public, omitting refused content cannot explain the refusal, and deferring one operation's fields is no guarantee for the enclosing request. The instance's own private material is different: private signing keys, signet and faucet keys, authentication tokens, the entire database connection configuration including host, port, user, password and transport-security parameters, proxy addresses, and any private reachability or operating detail are secrets. Every such value is secret-typed from acquisition wherever a deployment can supply it, including read buffers, parsed configuration and error fields, and remains so until the explicit access at the call that needs it (`dec:observe:secrets`), (`inv:observe:secret-boundary`); only material a test generates for a disposable instance is governed instead by (`conv:observe:fixture-secret-exits`). Observing a secret records its declared role and the type's redaction marker, never its exposed contents; no role string contains the private value. This is representation by construction, not filtering an observation after it is formed. Metric attributes remain bounded categories solely to control cardinality; traces carry the full public detail, including identifiers, payloads and error structure. Levels and sampling govern delivery under (`rule:observe:sampling`), not selection of fields inside a delivered observation. Dependency observations carry their full content and a checked label mapping identifying dependency origin; they do not impersonate repository-owned claims.

**Invariant (Observation independence)** · `inv:observe:noninterference` No binding computation reads a span, metric, exporter response or clock. It reads only public inputs, declared procedures and deterministic resource-budget counters; those counters flow one way into metering, never back from it. Observation does not choose act order, recipients, rungs, rounding, limits or verdicts. With identical public inputs and deterministic budgets, executions that complete with observation enabled, disabled, filtered, sampled or export-failed yield identical verdicts, standing and canonical published bytes. Telemetry is outside the publication package and replay's binding comparison. Runtime timestamps and elapsed times are operational evidence only; input effective boundaries remain authoritative public data. Observation overhead may affect operational latency, but must not consume binding work budgets or convert a completed mathematical answer into another answer; an externally cancelled run remains incomplete and publishes no verdict inferred from its clock. Telemetry allocation and callbacks must be bounded, non-panicking and isolated from binding errors.

**Proposal (Executable coverage gate)** · `proposal:observe:enforcement` Accepted implementation plan: an observability gate parses Rust syntax and the declared supported build configurations, enumerates every first-party public function body and named operation, and joins them to a checked operation registry naming owner, source item, claim citation, span boundary, fields and metric declarations. The design-operation registry also accounts for private entry points, asynchronous task roots and scripts through labelled process operations; reject missing, duplicate, stale and unresolved mappings. Recognize a reviewed instrumentation attribute or explicit scoped helper whose arguments are checked, rather than trusting a text search or the presence of a tracing import. Generated and macro-expanded entry points need an expansion-aware census or an explicit checked generator mapping; inability to inspect one fails coverage. An item-local exception names exactly one coverage rule and includes a Justified complete sentence explaining bootstrap, recursion prevention, const evaluation or inherited context, together with a witness showing the enclosing labelled boundary. Review all arguments, results, error variants and Debug fields for full recording, using mechanical checks for explicit skip or content-filter syntax and reviewer-confirmed items for semantic coverage. Review secret acquisition and typed data flow wherever a deployment secret can be present: a field identified by its role, name or type as a credential or private operating detail must use the secret carrier, never an unprotected string or scalar; a test's own disposable material is not so classified by its role, name or type (`conv:observe:fixture-secret-exits`). Review enclosing secret aggregates so the whole connection configuration is protected, not only a password field. Inventory every ExposeSecret call and verify its immediate necessary consumer, temporary lifetime, retained state and error paths under (`inv:observe:secret-boundary`); names alone cannot detect a secret copied into an ordinary error. Review parser, driver, exporter and child-process boundaries with negative leakage probes and compile-fail checks. There are no file-wide or test suppressions, and an exception does not waive secret typing or observation independence (`dec:lint:policy`). Instrumentation internals use a bounded nonrecursive loss path; initialization has a labelled bootstrap record and transfers its timing into the root operation after installation. The gate verifies ordinary citation resolution without changing record 001's adoption parameters. Owner: the foundation implementer and repository reviewer; implementation admission requires a working census and negative probes, not the accepted plan alone. The foundation bite records full recording, secret data flow and ExposeSecret consumers as reviewer-confirmed items with negative probes wherever syntax cannot decide them. The mechanical census proves only its syntactic checks; it must never present these reviewed obligations as mechanical proof. Observation inputs are independently keyed fragments under ownership domains, discovered from the Git index within the declared registry root. An operation and its review share one fragment; common shapes and assessments remain separately keyed. The shared reader rejects duplicate identities even when their values agree, merges in identity order and checks references before expansion, so enumeration order cannot change an operation or its reviewed evidence.

**Gate (Foundation evidence)** · `gate:observe:foundation` Before any domain bite, bring documents, pn-interchange, cli-common, execwrap under the coverage gate in (`proposal:observe:enforcement`). Exercise omitted instrumentation, wrong owner/label, stale operation, duplicate metric name, undeclared unit/attribute, and invalid exception as failing fixtures. Runtime witnesses cover success, refusal, error, cancellation, unwinding and asynchronous context, without claiming a completion after process death. Compare disabled, enabled, sampled and failing-export runs for identical deterministic results and output bytes; verify bounded cardinality, loss accounting, no recursive observation and unchanged stdout. Prove secret Debug output exposes only the marker and role, Display is unavailable, and accidental serde serialization is rejected; test nested errors and tracing without string sanitization. Exercise secret-owned reads and parse failures, whole connection configurations, explicit exposure consumers, driver errors and drop zeroization. Test that all public arguments, results, SQL parameters, payloads, numeric witnesses and errors are recorded in full when delivered. A dependency that copies private material into printable errors or its own events does not pass this gate merely because its input was a SecretBox. Metering tests use controlled clocks outside binding computations and independently counted work. This gate lands as code in the foundation observability bite (`gate:design:observability-foundation`); it is not implemented by this documentation change. Existing checks remain mandatory throughout. Discharge the bridge/version/credential obligations of (`proposal:observe:export`) and retain the separate mechanical and reviewer-confirmed results of (`proposal:observe:enforcement`).

**Decision (Secrets library)** · `dec:observe:secrets` Adopt secrecy with SecretBox and SecretString as the secret carriers and ExposeSecret as the explicit access boundary. Their redacted Debug, absence of Display, lack of serde serialization without deliberate supported opt-in, and zeroization on drop prevent accidental printing of a wrapped secret. Do not opt secret carriers into observation serialization: the observation representation is the marker and role. Private configuration is one secret-owned aggregate whose contents support zeroization; numeric and address fields are no less private than password bytes. Introduce the dependency in the foundation observation bite, review its version and required features there, and use it in subsequent storage and key-consuming code. These properties make secrecy the selected library; dependency resolution and adapter evidence remain implementation work. Surface evolution follows (`rule:compatibility:pre-one`).

**Invariant (Explicit secret boundary)** · `inv:observe:secret-boundary` ExposeSecret is permission to borrow private contents for a necessary call, never permission to format, log, serialize for observation or retain an ordinary copy. Read private input into secret-owned storage and parse within that boundary; no intermediate public String, generic JSON value or parser error may retain private bytes. Ordinary diagnostics retain full public error structure, with private fields still secret-typed. The library cannot control what a consumer does with an exposed reference: driver, parser, cryptographic, transport and process integrations must preserve the same invariant in their retained state, errors and events. Admit an integration only after that contract is established; a driver that embeds a connection value in an ordinary string error is incompatible, not made safe by wrapping its input or by an output scrubber. Its raw errors can be recorded unsanitized only when this construction is satisfied. Zeroization covers the owned secret storage on drop, not copies made outside its protection. This is an implementation obligation with evidence at (`gate:observe:foundation`), not a claim that choosing a dependency alone proves end-to-end secrecy.

**Amendment (Ordered reserved drain)** · `amend:observe:ordered-drain` Repository amendment: (`amend:observe:compact-content`) keeps the reserved drain-request slot so a full ordinary queue cannot reject the request. Before acknowledging a request, the worker drains up to the ordinary queue capacity after taking that request. Every ordinary record enqueued before the request lies in that FIFO prefix; later sends cannot overtake it. Reserved diagnostics and summaries are drained before acknowledgement too. After each prefix and acknowledgement, the worker takes another accepted request if the reserved slot is occupied, until the slot is empty before returning to the blocking record receive. A prefix may consume a later request’s wake, so one slot check per batch does not suffice. The overlapping-drain control holds the first prefix by an event, places the second request and its wake, and requires the second acknowledgement at the pre-park event. Remembering a consumed wake is set aside because rechecking the slot holds this invariant without additional state; retries, re-sent wakes, sleeps or a different timeout do not establish it. Test-build acknowledgement and fixture-event waits have named hang containment with caller locations. The windowed test-build wait is pinned at its 600-second containment; the fixture-event caller control checks the message on a disconnected channel, not an elapsed timeout or the complete acknowledgement route’s bound; complete-evidence waits in deployed code still wait for acknowledgement, and production windowed drainage and loss accounting are unchanged. **Decision (First-start credential route)** · `dec:observe:first-start-route` Select a supervisor-owned initialization operation whose repository generator runs under a disposable unprivileged identity, separate from both the instance and store accounts. The intended installation supplies no network, a read-only system view, no writable path and two private named output descriptors per role invocation: password and verifier, each connected directly by a kernel pipe to its own supervisor sealer under administrator custody. Before acquiring entropy or generating either output, the generator requires exactly two descriptors passed through the supervisor's descriptor-passing convention, named password and verifier. It refuses a missing descriptor, a wrong or repeated name, or any additional passed descriptor. Descriptor position or an unnamed extra channel cannot substitute for this closed role roster, since it could send private material to the wrong receiver. The names are public capability metadata; passing them through the convention introduces no secret environment value. Public diagnostics use the two standard streams as a separate channel retained by the supervisor per invocation. This wiring is the operator's intention pending rehearsal under (`open:observe:credential-installation`), not an observed installation property. No shell, intermediary utility or file carries the plaintext. Only the administrator's publication step handles the resulting sealed files; no repository executable runs under administrator authority at this or a later stage. A generator under administrator authority is set aside because generation needs no such authority. A sealing interface inside the secret container is set aside because it would add provider and key custody to the repository when the supervisor already owns them. If the supervisor cannot establish that wiring, the operator intends an administrator-owned launcher to establish the same pipes and sandbox around a process dropped to the disposable identity before repository code executes, with notice and a new installation witness before use. Moving sandbox enforcement to that launcher is not permission to run repository code with privilege. The launcher-made wiring is the only fallback; a supervisor entropy producer is withdrawn from the fallback contract because no protected verifier derivation with reviewed entries, exits, pairing and no-plaintext-server evidence is selected for it. Neither an ordinary exported buffer nor server-side derivation from a password is a fallback.

The passed-output boundary selects kernel duplication through a handle for this process in pn-secret-home, using the existing locked rustix process feature: pidfd_open for the current process and pidfd_getfd for only the two convention-selected numbers, with empty flags. The kernel returns a new owned descriptor for each; no Rust owner is asserted for an inherited number. The implementation and finite acquisition controls are ``[SECRETHOME-def:home:named-delivery]``; the generator remains a separate introducing cut. This is a reviewed use of an existing safe kernel-allocation interface, not a registry wrapper around an unchecked ownership conversion. The private constructor accepts no caller-supplied process handle or descriptor number. The current-process handle is never obtained from the environment; the environment's addressed process is checked against the actual current process. The process and both owned duplicates must be acquired before entropy; the optional process-handle identity check follows duplication, and the process handle is released before validating the duplicate pipe endpoints. The constructor's latch is consumed on the first attempt, including refusal, and never reset. It runs before workers, protection setup or other descriptor-opening work; it rejects any newly allocated handle in the reserved range zero through four, so a missing public standard stream or inherited output cannot be filled by acquisition itself and then mistaken for its original role. Refusal releases every new handle before any public diagnostic is attempted; no diagnostic is written through an acquisition-created handle in a public stream slot. The safe duplicates are checked as distinct writable pipe endpoints before entropy. The code cut owns the source census and fault controls for this ordering, the syscall refusals and slot-reuse refusal. No operation targets another process, exposes an untyped handle or changes the originals' shared file status flags. The library's warning about affecting a target's existing Rust I/O assumptions is addressed by this closed startup scope: these are the supervisor's inherited pipe ends, not another live Rust object's descriptor offered by a caller.

The six mapping sites and their inventory remain unchanged under (`amend:lint:secret-home-unsafe`). The alternative of one additional inventoried adoption site keeps the single-owner rule but adds an ownership obligation that convention metadata and a once-only latch cannot by themselves prove; it is set aside because fresh kernel duplicates need no adoption of the originals. A registry helper merely hiding that adoption is set aside because it moves rather than discharges the obligation and grows the closure. Reopening through the process descriptor directory is set aside because a pipe inode's permissions can refuse a disposable identity even though its inherited descriptor is usable. Using public standard streams is set aside because it consumes the separately required diagnostic channel; assigning role names to those streams would not restore that channel. The selected process interfaces are already in the locked process feature and add no crate, feature or authority over another process. They do add two syscall kinds and at most three temporary owned handles, not locked secret storage. Their availability in the exact sandbox remains an installation witness: refuse unavailable or denied duplication before entropy; do not add privilege, weaken protection or silently fall back to adoption. The current-process access check does not depend on ownership of the pipe inode or a writable path.

Read the public convention as LISTEN_PID equal to this process's decimal identifier, LISTEN_FDS equal to two, and LISTEN_FDNAMES containing exactly password and verifier once each, separated by a colon. The descriptors start at three and are contiguous; either name order is accepted and each name selects its corresponding number, never a positional password assumption. Missing or malformed addressed-process metadata, an absent count, a count below two or an unavailable required handle refuses as missing; a valid count above two refuses as additional before any attempt to adopt its numbers; with count two, a missing name list, wrong name, repeated name or wrong number of name entries refuses as name mismatch. Malformed or overflowing counts refuse as invalid convention, never as zero or a reason to scan more numbers. These are public refusal classes before entropy, not dependency error text. The selected convention requires the addressed process field. If LISTEN_PIDFDID is present, also require its decimal value to match the inode of the acquired current-process handle; missing support or mismatch refuses as invalid convention, never silently ignores the extra identity check. Names are parsed as bytes of the exact roster, not normalized or guessed. The admitted process feature cannot safely establish the handle filesystem's identity support, so the implemented reader refuses every present optional identity rather than accepting an unproved inode comparison. A supervisor that supplies this value cannot run the generator; the installation must witness its omission. The reader does not call a helper that clears the environment: these values remain unchanged, are recorded as public inputs and are not passed to a child because this terminal process spawns none. Mutating the environment would add another unsafe obligation in the workspace's edition and is set aside. A second acquisition refuses from the latch even if these values remain present. Descriptors inherited outside the convention means any open descriptor at entry other than the public standard streams and the two declared numbers, including an undeclared duplicate of either write end. Their absence and the exclusive named receiver wiring are supervisor sandbox witnesses, not claims that parsing the convention discovers every inherited descriptor.

The delivery surface has distinct opaque password-receiver and verifier-receiver types, constructed only by that named acquisition, with private owned handles and no conversion between roles. The protected credential offers a password delivery accepting only the password receiver and a verifier delivery accepting only the verifier receiver; each consumes its receiver, borrows only its own protected region and returns a content-free success or typed public failure with public byte progress, never bytes or a writer. The caller cannot supply a destination to the other role's operation. Receiver identity is supplied by the supervisor: types prevent swapping already named capabilities, not a supervisor that mislabels a pipe. The two source-local exits are the checked password region to its password pipe and the checked verifier region to its verifier pipe; each code site must name its material, sole destination, borrow lifetime and kernel copy under (`rule:observe:secret-exceptions`). There is no generic write or callback surface and no retained ordinary buffer. Write directly from the checked region; advance on positive short writes, retry an interrupted call without resending an accepted prefix, and refuse zero progress, a closed reader or any other write failure with a constant diagnostic. A deadline or termination that prevents completion is failure, never a partial success; the existing executable wall-time contract still applies. A write success records bytes accepted by the kernel, not receipt, sealing or publication. The kernel pipe buffer contains private password or verifier bytes until read or released; it is kernel and receiver custody outside the locked homes, not a claimed erased mapping. The two inherited originals are deliberately left open and never wrapped, closed by remembered raw number or used for writing by repository code; process exit releases them. Dropping a duplicate alone cannot produce EOF while its original remains open. Dropping the owned handles requests close exactly once in safe code, but returns no close result: no success record claims checked close or receiver EOF. Retrying a close by remembered number is set aside because that number may have been reused. End of input requires every write-end duplicate to close; the supervisor must release its writer duplicates and the reader must observe EOF independently. Every observable delivery and home-completion failure yields a nonzero exit, including after a full write. Destroying a handle supplies no close confirmation. Missing end of stream after process exit means another writer reference remains; the receiver's release witness, not a destructor result, establishes end of input. Broken-pipe handling must preserve the runtime's public failure path, with the installed signal disposition witnessed; abrupt termination is a failed invocation, not a success object. The generator establishes (`amend:crypto:secret-home`) before acquiring entropy. For each role it generates 32 independent random bytes directly into protected storage and forms exactly 64 lowercase hexadecimal ASCII password bytes there, with no terminator or newline. This preserves 256 bits of entropy when the operating-system source meets its contract and fits the admitted printable-ASCII password profile without normalization or escaping. The two roles are generated by separate sequential invocations; neither is derived from the other. A consumer-specific protected operation writes the password directly from its checked home to its password descriptor. It returns no byte buffer, generic writer callback or serialization accessor. The generator writes exactly 64 password bytes and exactly 135 verifier bytes, each followed by end of input, or exits nonzero, including a failure after a full write. A short, overlong, trailing or unterminated stream is no credential. The supervisor sealer reads to end of input without enforcing a plaintext length. Publication witnesses length by comparing each sealed length measure with the value calibrated for that exact plaintext length under the same fixed credential name, together with the successful generator invocation record. The deployment names the measure and its computation before calibration: it is computed from the sealed file’s bytes alone, without decryption or any reader of the plaintext, and may be the raw file size or a length determined by the public encoding, such as decoded length computed from text length and padding characters. A measure that assumes a file form, such as one unbroken padded text using the declared alphabet, refuses a file outside that form and never normalizes it. Raw file size as the only admissible measure is set aside because an encoding that groups bytes can make it constant across adjacent plaintext lengths. Before any stream is accepted, the installation must establish the following premise under each fixed credential name: sealed length measure depends on plaintext length alone, not content; it never decreases as length grows; and it strictly increases from one byte below to the required length and from that length to one byte above. Together these properties exclude every other plaintext length from the required length’s sealed length measure. The sealing format’s own stated law for the declared measure, where available, establishes content-independence and non-decrease for all lengths; installation measures the three-point strictness exactly and tests at least two distinct contents per tested length. Measurements can only corroborate the first two properties over the lengths and contents tested, so a witness resting on measurement alone is conditional on that sampled range and explicitly says so; it establishes no all-length premise. A measure equal to plaintext length plus one constant under a fixed name is the simplest affine law satisfying all three properties; calibration records that constant and checks it for every tested input under that name, without promoting sampled agreement to an all-length law. A three-point measure increase alone is set aside because content dependence or a decrease elsewhere can give another length the same sealed length measure. Changing the declared measure, its computation or the sealing format voids its calibration; repeat the full premise witness and calibration before accepting another stream. A declared measure that violates this premise makes the sealed length measure witness void and no stream is accepted on it; success cannot rescue an invalid sealed length measure witness. Decrypting or introducing a plaintext reader merely to count bytes is set aside because it would add another holder of the secret. A gate model can check the comparison and refusal logic with declared measure values and invocation results, but cannot establish the installed measure's premise. Readers cannot observe generator completion. Before any link into place the administrator publication step also requires the supervisor's record for the invocation whose streams it holds: the unit ended, its result is success and its main process exited with status zero. A completed sealer or correctly sized temporary file supplies none of that completion evidence. The password can leave that container only on its password descriptor. The configuration library's representation is unchanged; the executable adapter and its source-local exits remain held. Sealing and protected delivery have their own copies under administrator custody, not a claim that every copy remains in the repository mapping.

The environment must permit anonymous private mapping, dump/fork exclusion advice, memory lock and unlock, unmapping, process identity and resource-limit queries, changing and verifying dumpability and both core limits, kernel entropy, and the read-only process metadata operations on which mapping ownership depends. **Model (Credential initialization states)** · `model:observe:credential-initialization` Absence alone authorizes nothing. The administrator's intended first-initialization publication protocol, pending (`open:observe:credential-installation`), reads three prerequisites under its exclusive publication lock: an existing unconsumed new-instance authorization naming the instance, its public identity and the operator's local creation reference; empty admissible store state; and absence of a credential set. Refusal names the failed prerequisite without private paths. The generator has no store access. The creation reference and supervisor invocation references correlate local installation records only: no repository identity recipe, digest, public identifier format or byte assignment is introduced. Reusing a consumed authorization after store loss is set aside because it would silently recreate an established instance.

The intended publication unit is the complete set for both roles, each password with its verifier companion. First initialization and rotation use distinct authorization classes; neither may admit the other operation. After the supervisor completion check for both invocations and the sealed length measure witness under (`dec:observe:first-start-route`) for all ended streams, the administrator writes each sealed file beside its final name, synchronizes it and links it without replacement; it synchronizes the directory, links a completion marker last and synchronizes the directory again. The nonsecret marker records logical file names, sealed length measure values with their declared measure, generator invocation references and the authorization's creation reference, not secret bytes or private paths. Every consumer and provisioning step requires this marker and validated set before reading. A marker is not a substitute for the completion check that authorized publication. File-by-file usability is set aside: without the marker, files are an incomplete set and recovery discards the whole set under the lock, never completes it from parts. Unsupported durability or no-replace semantics refuse. These filesystem operations and role changes are separate transactions; readiness requires reconciliation of both.

Rotation is an in-instance credential change, not a replacement public instance. The operator intends a distinct rotation authorization naming the instance, the creation reference of the complete set it supersedes and a new creation reference, pending (`open:observe:credential-installation`). Under the same publication lock, require that authorization to exist and be unconsumed, the named superseded set to be complete and currently selected, the store to be admissible and nonempty, no incomplete set to stand and no earlier superseded set to remain retained; each failed prerequisite refuses by public cause. The candidate marker carries the new creation reference, associating the set with its authorization. A new-instance authorization cannot authorize rotation or the reverse. Requiring a new instance for every credential change is set aside because it would discard the public identity and store for an operational event without making role recovery safer. These references remain local administrative correlations, not new repository identifiers or encodings.

The operator intends a distinct candidate directory with its own last-linked marker, produced under the same exact framing and same-invocation supervisor completion checks as first initialization, while retaining the old complete set. Consumers are stopped for the whole rotation. While a rotation authorization stands unconsumed, no consumer may start. The authorization ends only by a synchronized rename without replacement: consumed after selection changes, logins are enabled and protected login checks pass; or abandoned after every role has been restored to the superseded set and that set is selected. Neither ending removes its history. Consuming at selection is set aside because a crash before login checks would end that explicit no-start condition too early.

The intended selection is one administrator-owned name in the instance's administrator-only store directory resolving to exactly one complete set directory; all units' credential paths and marker prerequisites use that name, read only at start. The administrator changes it only after every role's private read-back equals the target set's verifier and required attributes, with logins disabled and sessions drained. Make a new selection link beside the existing one, synchronize the directory, rename the new link over the old selection and synchronize the directory again. This is the sole replacing operation: files and markers of a set are linked without replacement; the consumed new-instance authorization, consumed or abandoned rotation authorization, ended rollback record and discarded set each use the following no-replace ending rule. Source name alone present means the act has not ended; destination name alone present means it has ended, and retry recognizes that state without changes. Both names present on different objects is a collision and refuses with everything unchanged. For file endings only, both names identifying the same device and inode are an interrupted link-then-unlink ending, completed by removing the source name and never treated as a collision; equal inode numbers on different devices are different objects. A directory ending uses an atomic no-replace rename and has no link-then-unlink intermediate state. The disposal-absence reading applies to a discarded superseded set after removal: when neither directory name exists and the durable recorded administrator act names exactly that set, disposal has ended; retry recognizes that state without changes, completes only its acknowledgement and treats it as neither collision nor missing material. Without that matching recorded act, both names absent is missing material: refuse unchanged and freeze for the administrator, without regeneration. An incomplete candidate has no authority, so its absence needs no ending proof and is the pre-publication state; retry still requires the unconsumed authorization and the applicable initial prerequisites. Rollback-record endings belong to the role-and-rollback model. A separate durable disposal completion mark is set aside because its own acknowledgement can be lost while the recorded act already distinguishes the two cases. Freezing every both-absent reading is set aside because the authorized outcome and observed state coincide in the completed-disposal case, so that freeze adds an administrator stop without a safety gain. These readings retain the required synchronization and publication lock; unsupported primitive semantics refuse. Only selection is replaced atomically. Replacing an ending is set aside because it would erase the history needed to distinguish a completed act from a new one. Every observable selection names an old or new complete set; uncertain durability prevents start until reconciled. A unit never changes it. These are operator intentions pending the installation witness, not established filesystem properties.

Recovery reads five things under the publication lock: the initialization or rotation authorization state, the complete sets, the selected set, every role's private read-back and any separate rollback authorization with its direction and ending. They determine whether to discard an incomplete candidate and abandon, continue or abandon a complete unchanged candidate, finish new roles and selection or restore every old role and abandon, or finish login checks and consume when selection is new. Recovery never regenerates. Abandonment requires verified old-role equality and the old selection, not merely an intention to roll back. Missing complete companions, unknown role state or contradictory records freeze recovery. Rollback does not reverse data or schema changes and requires compatible schema and known role attributes.

The operator intends a rollback after forward completion to have its own authorization, written before its first act, naming the instance, the selected set it leaves, the retained superseded set it returns to and its direction, pending (`open:observe:credential-installation`). While that record stands unended, no consumer may start. Recovery follows that recorded direction: stop and drain consumers, disable logins, restore every target verifier and attribute, privately confirm every equality, replace selection, enable and check logins, then end the record by a synchronized rename without replacement, never removal. Missing or contradictory authorization or readings inconsistent with its direction freeze for the administrator; consumed rotation history with mixed roles alone implies no recovery direction. The earlier consumed rotation authorization is history, never reopened or reused. After rollback the departed set is the single retained superseded set; a new rotation waits for its explicit recorded discard. Always freezing an interrupted authorized rollback is set aside because its recorded direction supports the same safe reconciliation as rotation. These are intended installation procedures, not a new repository identifier or record encoding.

The operator intends exactly one retained superseded set and no automatic disposal. Only an explicit recorded administrator act binding the set to dispose of by its creation reference, as the marker does, after new login checks, consumer restart and reported readiness confirm activation, may end rollback. The act refuses while any unended rollback authorization names its set, including before the first stop. Write the whole act under a temporary name and link it into place without replacement, as for a set file and its marker; synchronize that act before the first rename, so every post-rename state retains it; the record remains after the directory is removed. The durability of that ordering and the atomicity and durability of the directory primitives remain installation witnesses. It renames the unselected, unused superseded directory to a discarded name without replacement, synchronizes and removes it; admission of a new rollback ends at the written disposal act, and the set’s material ends at that rename, including after an interrupted removal. Reconciliation must no longer depend on the old set. Until disposal, a second rotation refuses. The retained consumed or abandoned authorization histories are never removed by this procedure. The disposal and selection operations, their ordering and crash recovery remain owed installation evidence under (`open:observe:credential-installation`).

A present disposal act commits its named set to disposal: recovery synchronizes a present act whose synchronization is unconfirmed before any further step, and then finishes the disposal without undoing it. A present act not readable as binding exactly one set by its creation reference arises only through damage or a write outside the admitted transitions and freezes recovery, as contradictory records do. A present act is never treated as absent; this single admission threshold preserves its intent across an interrupted synchronization. Once an act binding that set by its creation reference is present, a new rollback authorization naming it refuses unchanged with a public reason naming the standing disposal. Before the act, the complete retained set remains eligible for rollback authorization; after the act, the remedy is forward, a new rotation after disposal ends, not return to the old credentials. Admitting a new rollback until the rename is set aside because it deliberately creates contradictory records whose only outcome is an administrator freeze and gives the disposal-absence reading a second history.
