## Observability · `sec:observe:record`

**Decision (Foundation)** · `dec:observe:foundation` Observability precedes the first domain crate. Every operation that does work executes within a tracing span; every span and event identifies the repository claim, contract or algorithm it executes. Every operation has work, resource and elapsed-time accounting and declared metrics, including refusal and incomplete execution. Introducing these obligations before implementation makes coverage reviewable at each new contract rather than leaving unobservable paths to retrofit. An operation's trace explains which labelled work ran; it does not prove that work correct (`cav:labels:non-normativity`).

**Rule (Operation boundaries)** · `rule:observe:spans` Each public function body and named design operation has an operation span, with nested spans for independently accountable stages. Private helpers execute within the caller's span unless they establish a separate work or resource boundary, in which case they have their own. Propagate context across asynchronous suspension, spawned tasks and worker threads; instrument a future through its execution rather than retaining an entered guard across an await. Cancellation, error, panic unwinding and normal return close accounting with distinct outcomes; abrupt process loss leaves an incomplete operation, never a fabricated completion. Libraries emit instrumentation without installing global subscribers; the executable owns initialization and export. Bootstrap and instrumentation machinery require the narrow exceptions in (`proposal:observe:enforcement`), not an unlabelled escape from the discipline.

**Convention (Names and fields)** · `conv:observe:names` The static span or event name is its primary repository label text, with explicit claim_owner and claim_label fields; execution_owner identifies the emitting crate's owner. An operation field distinguishes operations of one contract, and an event_kind field distinguishes start, progress and completion. Each event carries these fields even if its parent span was filtered out. A formation span names (`alg:design:formation`), for example. Runtime strings are data, not fresh mints or a new synthetic-citation class: a checked source mapping pairs each constant with an ordinary resolving citation, including the declared owner import where needed (`inf:labels:synthetic-citation`). The checker validates that pairing; binding code never loads the label graph. Metric stems encode lowercase execution owner, claim owner, kind, area and name with double underscores between components and single underscores replacing name hyphens, followed by a double underscore and the declared measure/unit suffix; the restricted label alphabet makes the component encoding reversible. The gate rejects duplicate exported names, including exporter normalization collisions. Trace fields use fixed snake_case names with declared types and units, never user-supplied keys. These names may change freely before 1.0 under (`rule:compatibility:pre-one`).

**Rule (Metering)** · `rule:observe:metering` An operation records monotonic elapsed wall time from entry to terminal outcome, including waits, in seconds; task suspension is included. Work is counted in declared units such as acts, edges, iterations, bytes or queries; account retries and refused attempts explicitly. Resource accounting distinguishes current usage, high-water usage and cumulative traffic, and declares whether a measure is exact, estimated or unavailable. Never substitute zero for an unavailable CPU or allocation measure. Parent durations are inclusive and are not summed as disjoint work; each work increment has one owning operation, and any aggregate states its roll-up rule. A completion record carries duration, outcome and totals; incomplete records carry known partial totals. This becomes the uniform wall-time evidence for actions and child-process execution, replacing independent script timers only after the foundation gate proves coverage. Existing gate wall reporting remains until then. Gate resource samples keep process accounting, sampled cgroup accounting and system-wide kernel observations separate. Read the unified hierarchy mount, the sampler’s own cgroup path and namespace init’s path. A sampled hierarchy mounted at its root with both processes at that root is labelled namespace-root-cgroup, as on the supported container route; other readable hierarchies are labelled shared-or-unproven-cgroup, without asserting another workload is present. Missing hierarchy evidence remains hierarchy-unavailable-cgroup. Retain recursive cgroup.procs membership and readable member paths separately as snapshot evidence. A process exiting during that enumeration makes membership unavailable, not the stable hierarchy identity; it must not change the node comparison key. These labels establish neither exclusive gate ownership nor uninterrupted membership between samples. No cgroup is called the gate’s own solely because it is sampled. Its usage and pressure never stand for node-wide activity. At each gate and step boundary, retain system-wide /proc/pressure/cpu, memory and io counters, /proc/stat CPU ticks and boot time, and the first three /proc/loadavg averages beside the cgroup samples. The proc readings are labelled node-wide with source proc-systemwide only when the sampled proc path is a procfs mount and none of pressure, stat or loadavg is shadowed by a subordinate mount; absent provenance leaves the source unavailable. The node identity records the observed source and cgroup scope, rather than fixed scope strings. On Linux the kernel’s procfs PSI totals and aggregate CPU ticks have system-wide scope; the loadavg task counts and namespace-local last process id are not node-load evidence. A bracketed host/container comparison establishes this visibility on the supported worker without generating competing load. Node busy cores divide the busy tick delta by the kernel clock tick rate and elapsed wall; guest ticks already included in user ticks are not added again. PSI fractions divide cumulative stall deltas by elapsed wall, never differences of rolling averages. Missing readings, backwards counters or a changed boot leave the affected node observation unavailable. Cgroup deltas remain named cgroup deltas, with no fallback into node figures; process-and-child CPU remains the gate's own accounting. Overlapping intervals are context and cannot be summed as disjoint resource use.

**Convention (Metrics)** · `conv:observe:metrics` Every operation exposes counters for started and completed operations and work units, a gauge for active operations and declared live resources, and histograms for elapsed seconds and workload sizes. Completed counters distinguish bounded outcomes, including cancellation and observation loss where applicable; process death may leave starts unmatched. Decrement active gauges on all orderly exits. Each metric declaration gives its owning label, measure, counter/gauge/histogram kind, unit, aggregation rule and finite attribute vocabulary; histogram boundaries are reviewed operational settings. Metric attributes contain only bounded categories such as outcome, operation or refusal class. Never use an act identifier, epoch, address, request identifier, raw label supplied by a caller or error text as a metric attribute. Counts of work are observations of performed work, not counts of proven claims. Names follow (`conv:observe:names`) and (`rule:compatibility:pre-one`).

**Decision (Sinks and ownership)** · `dec:observe:sinks` Executables send traces, completion metering and metric summaries as JSON to stderr under (`rec:output:decision`); stdout remains the command's result stream. Long-running services additionally export traces and metrics through bounded queues with explicit loss accounting. The application composes the subscriber and recorder once; reusable libraries neither replace them nor initiate exporters. Operational service export settings belong in the database under (`rule:storage:configuration`), not an additional configuration file; connection-only bootstrap uses local stderr before those settings are available. Emission follows (`amend:observe:emission-levels`); legacy verbosity arguments do not silently enable payload persistence. Private export endpoints and authentication material are secret-typed and observed as role and redaction marker under (`rule:observe:privacy`); all public content is recorded in full. Export loss, queue saturation or a disconnected sink cannot block or fail binding computation; reporting uses reserved bounded resources, and lost observations remain disclosed as loss rather than silently interpreted as zero work.

**Proposal (Collection and export)** · `proposal:observe:export` Accepted with implementation conditions: retain tracing and tracing-subscriber for spans and JSON, add a reviewed tracing-subscriber layer for operation accounting, use the metrics API for declared counters, gauges and histograms, and use tracing-opentelemetry with opentelemetry, opentelemetry_sdk and opentelemetry-otlp for service trace export. A single application-owned metrics recorder would forward the same declared instruments to the SDK's metric provider, with a JSON snapshot sink for executable summaries. This separates library instrumentation from deployment transport and avoids two independently counted metric systems. These collection and export roles are accepted, not claims that an off-the-shelf recorder or compatible version set has been established. The separate secrecy library choice is decided in (`dec:observe:secrets`); its integration is part of the same foundation bite. The foundation implementer must review APIs, licences, versions, feature sets, bounded queue behavior, metric translation, shutdown and secret-preserving dependency boundaries; the reviewer admits the demonstrated integration before dependencies are added. Exporter construction remains outside domain crates. A local recorder must work without a collector; failed export cannot hold a mathematical result hostage. Trace and metric surface evolution follows (`rule:compatibility:pre-one`). The foundation bite must name and review the bridge from the metrics recorder to the OpenTelemetry metric provider, prove a compatible version set and retain exporter credentials in the secret type throughout the integration. Acceptance of the roles does not establish that evidence.

**Rule (Levels and sampling)** · `rule:observe:sampling` Use INFO for operation lifecycle and bounded outcomes, WARN for degraded observation or operational conditions, ERROR for operational failure, DEBUG for diagnostic stages and TRACE for detailed progress. A mathematical FAIL or INDECISIVE is a typed completed verdict, not automatically an ERROR. Filter or sample detailed trace delivery by declared operational policy; record the policy and dropped-record totals so sampled absence is not evidence of no work. Accounting and metric updates run independently of trace filtering and sampling and do not extrapolate exact totals from sampled spans. If collection itself is disabled or unavailable, mark the observation unavailable. The design of operation contexts must therefore not rely on a subscriber receiving a filtered span. Deterministic work-budget accounting continues regardless of all observation settings (`inv:observe:noninterference`).

**Rule (Full observation and secret types)** · `rule:observe:privacy` Operations are instrumented to record their arguments, results, SQL parameters, errors including unsanitized driver errors, and Debug representations in full when full tracing is selected under (`amend:observe:emission-levels`). There is no content allowlist, argument skipping, payload suppression or sanitization step. Acts, records, ledgers, declarations, standing and publications are public network data; personal data in those public inputs is not a separate reason to withhold it. Full content explains what an operation did, while a hand-maintained filtering list drifts as fields and error paths change. At trace level a bounded operation formats its whole supplied input before its bound refuses it, a nested decoder formats content before an enclosing operation refuses, and a store read formats the whole store. Trace level is for exceptional debugging and is never the default: only a run requesting it bears this cost. Captured output is bounded by the capture limit, not by each operation's bound; that limit does not bound the work of formatting the input. Recording lengths before admission instead is set aside because network data is public, omitting refused content cannot explain the refusal, and deferring one operation's fields is no guarantee for the enclosing request. The instance's own private material is different: private signing keys, signet and faucet keys, authentication tokens, the entire database connection configuration including host, port, user, password and transport-security parameters, proxy addresses, and any private reachability or operating detail are secrets. Every such value is secret-typed from acquisition, including read buffers, parsed configuration and error fields, and remains so until the explicit access at the call that needs it (`dec:observe:secrets`), (`inv:observe:secret-boundary`). Observing a secret records its declared role and the type's redaction marker, never its exposed contents; no role string contains the private value. This is representation by construction, not filtering an observation after it is formed. Metric attributes remain bounded categories solely to control cardinality; traces carry the full public detail, including identifiers, payloads and error structure. Levels and sampling govern delivery under (`rule:observe:sampling`), not selection of fields inside a delivered observation. Dependency observations carry their full content and a checked label mapping identifying dependency origin; they do not impersonate repository-owned claims.

**Invariant (Observation independence)** · `inv:observe:noninterference` No binding computation reads a span, metric, exporter response or clock. It reads only public inputs, declared procedures and deterministic resource-budget counters; those counters flow one way into metering, never back from it. Observation does not choose act order, recipients, rungs, rounding, limits or verdicts. With identical public inputs and deterministic budgets, executions that complete with observation enabled, disabled, filtered, sampled or export-failed yield identical verdicts, standing and canonical published bytes. Telemetry is outside the publication package and replay's binding comparison. Runtime timestamps and elapsed times are operational evidence only; input effective boundaries remain authoritative public data. Observation overhead may affect operational latency, but must not consume binding work budgets or convert a completed mathematical answer into another answer; an externally cancelled run remains incomplete and publishes no verdict inferred from its clock. Telemetry allocation and callbacks must be bounded, non-panicking and isolated from binding errors.

**Proposal (Executable coverage gate)** · `proposal:observe:enforcement` Accepted implementation plan: an observability gate parses Rust syntax and the declared supported build configurations, enumerates every first-party public function body and named operation, and joins them to a checked operation registry naming owner, source item, claim citation, span boundary, fields and metric declarations. The design-operation registry also accounts for private entry points, asynchronous task roots and scripts through labelled process operations; reject missing, duplicate, stale and unresolved mappings. Recognize a reviewed instrumentation attribute or explicit scoped helper whose arguments are checked, rather than trusting a text search or the presence of a tracing import. Generated and macro-expanded entry points need an expansion-aware census or an explicit checked generator mapping; inability to inspect one fails coverage. An item-local exception names exactly one coverage rule and includes a Justified complete sentence explaining bootstrap, recursion prevention, const evaluation or inherited context, together with a witness showing the enclosing labelled boundary. Review all arguments, results, error variants and Debug fields for full recording, using mechanical checks for explicit skip or content-filter syntax and reviewer-confirmed items for semantic coverage. Review secret acquisition and typed data flow: a field identified by its role, name or type as a credential or private operating detail must use the secret carrier, never an unprotected string or scalar. Review enclosing secret aggregates so the whole connection configuration is protected, not only a password field. Inventory every ExposeSecret call and verify its immediate necessary consumer, temporary lifetime, retained state and error paths under (`inv:observe:secret-boundary`); names alone cannot detect a secret copied into an ordinary error. Review parser, driver, exporter and child-process boundaries with negative leakage probes and compile-fail checks. There are no file-wide or test suppressions, and an exception does not waive secret typing or observation independence (`dec:lint:policy`). Instrumentation internals use a bounded nonrecursive loss path; initialization has a labelled bootstrap record and transfers its timing into the root operation after installation. The gate verifies ordinary citation resolution without changing record 001's adoption parameters. Owner: the foundation implementer and repository reviewer; implementation admission requires a working census and negative probes, not the accepted plan alone. The foundation bite records full recording, secret data flow and ExposeSecret consumers as reviewer-confirmed items with negative probes wherever syntax cannot decide them. The mechanical census proves only its syntactic checks; it must never present these reviewed obligations as mechanical proof. Observation inputs are independently keyed fragments under ownership domains, discovered from the Git index within the declared registry root. An operation and its review share one fragment; common shapes and assessments remain separately keyed. The shared reader rejects duplicate identities even when their values agree, merges in identity order and checks references before expansion, so enumeration order cannot change an operation or its reviewed evidence.

**Gate (Foundation evidence)** · `gate:observe:foundation` Before any domain bite, bring documents, pn-interchange, cli-common, execwrap under the coverage gate in (`proposal:observe:enforcement`). Exercise omitted instrumentation, wrong owner/label, stale operation, duplicate metric name, undeclared unit/attribute, and invalid exception as failing fixtures. Runtime witnesses cover success, refusal, error, cancellation, unwinding and asynchronous context, without claiming a completion after process death. Compare disabled, enabled, sampled and failing-export runs for identical deterministic results and output bytes; verify bounded cardinality, loss accounting, no recursive observation and unchanged stdout. Prove secret Debug output exposes only the marker and role, Display is unavailable, and accidental serde serialization is rejected; test nested errors and tracing without string sanitization. Exercise secret-owned reads and parse failures, whole connection configurations, explicit exposure consumers, driver errors and drop zeroization. Test that all public arguments, results, SQL parameters, payloads, numeric witnesses and errors are recorded in full when delivered. A dependency that copies private material into printable errors or its own events does not pass this gate merely because its input was a SecretBox. Metering tests use controlled clocks outside binding computations and independently counted work. This gate lands as code in the foundation observability bite (`gate:design:observability-foundation`); it is not implemented by this documentation change. Existing checks remain mandatory throughout. Discharge the bridge/version/credential obligations of (`proposal:observe:export`) and retain the separate mechanical and reviewer-confirmed results of (`proposal:observe:enforcement`).

**Decision (Secrets library)** · `dec:observe:secrets` Adopt secrecy with SecretBox and SecretString as the secret carriers and ExposeSecret as the explicit access boundary. Their redacted Debug, absence of Display, lack of serde serialization without deliberate supported opt-in, and zeroization on drop prevent accidental printing of a wrapped secret. Do not opt secret carriers into observation serialization: the observation representation is the marker and role. Private configuration is one secret-owned aggregate whose contents support zeroization; numeric and address fields are no less private than password bytes. Introduce the dependency in the foundation observation bite, review its version and required features there, and use it in subsequent storage and key-consuming code. These properties make secrecy the selected library; dependency resolution and adapter evidence remain implementation work. Surface evolution follows (`rule:compatibility:pre-one`).

**Invariant (Explicit secret boundary)** · `inv:observe:secret-boundary` ExposeSecret is permission to borrow private contents for a necessary call, never permission to format, log, serialize for observation or retain an ordinary copy. Read private input into secret-owned storage and parse within that boundary; no intermediate public String, generic JSON value or parser error may retain private bytes. Ordinary diagnostics retain full public error structure, with private fields still secret-typed. The library cannot control what a consumer does with an exposed reference: driver, parser, cryptographic, transport and process integrations must preserve the same invariant in their retained state, errors and events. Admit an integration only after that contract is established; a driver that embeds a connection value in an ordinary string error is incompatible, not made safe by wrapping its input or by an output scrubber. Its raw errors can be recorded unsanitized only when this construction is satisfied. Zeroization covers the owned secret storage on drop, not copies made outside its protection. This is an implementation obligation with evidence at (`gate:observe:foundation`), not a claim that choosing a dependency alone proves end-to-end secrecy.

**Amendment (Ordered reserved drain)** · `amend:observe:ordered-drain` Repository amendment: (`amend:observe:compact-content`) keeps the reserved drain-request slot so a full ordinary queue cannot reject the request. Before acknowledging a request, the worker drains up to the ordinary queue capacity after taking that request. Every ordinary record enqueued before the request lies in that FIFO prefix; later sends cannot overtake it. Reserved diagnostics and summaries are drained before acknowledgement too. The cli-common drain-timeout fixture pauses the worker after its batch ends, queues one record or a full backlog before requesting the drain, and checks delivery at acknowledgement and at guard close without a timing verdict. The close path does not join the worker: (`amend:observe:delivery-cause-and-exit`) retains its bounded drain and synchronous disjoint delivered, lost, queued-undelivered and in-flight disclosure, because joining a blocked writer would remove the exit bound. Successful drainage now obeys the same prefix ordering; deadline or disconnected paths still disclose outstanding work rather than asserting delivery. The cutoff and shared-transport witnesses retain the unstarted-publication refusal and in-flight accounting.

**Amendment (Secret canonical encoding)** · `amend:observe:secret-canonical-encoding` The interchange library admits a protected canonical input tree for commitment computation. Private byte strings, text and integers enter in the workspace secrecy containers; arrays expose their structure, and explicitly public fields retain ordinary full observation. The protected and public routes share the canonical traversal and head-writing primitives. Protected encoding first checks a conservative allocation ceiling, allocates protected output once, and lends it only to the encoder; the next labelled borrower is the hash consumer. Nonces, salts, payloads, dependency fields and private pre-digests never enter ordinary observed Value fields. The original public API and its canonical bytes and full tracing remain unchanged. Every protected borrow has a separate reason and Caveat under (`rule:observe:secret-exceptions`); neither argument filtering nor subscriber replacement implements this boundary. Privacy rests on secrecy-typed inputs and output and the labelled, justified, census-counted exits: no private byte enters an ordinary Value, Debug, Display or span field. The fixed-vector and protected/public byte-equality witnesses check correctness, including traced execution; they do not establish absence of leakage by searching trace representations, entropy, custody or commitment authenticity.

**Amendment (Supervisor credential entry)** · `amend:observe:supervisor-entry` The designed node consumes each instance secret once per process lifetime from the supervisor-provided credential directory, after establishing the secret-home process protections. It receives a directory capability and known credential roles, never secret bytes in arguments or environment variables. It validates the supervisor's ownership and access contract, refuses symlink/substitution/oversize/incomplete input, reads bounded bytes directly into a secret container and retains only that container for subsequent uses. Original acquisition errors cannot escape with private paths or values. Failure refuses startup without a fallback to a home file, password prompt or database-stored copy. Rotation means a new credential set and a process restart, not an unobserved reread. A consumed secret is not repeatedly imported at each connection. The credentials remain available for the supervisor's next start in node-local protected storage outside the process; the administrator of the machine can read every secret of the instance. This is a custody limit, not a defect that Rust containers remove. Instance keys originate on this node on first initialization, never in a build checkout, fixture or deployment bundle; loss of the node-local key store starts a new publicly identified test instance, not an undisclosed replacement key in the old run. Before the package revision it has no test chain; the test chain belongs to the replacement instance after the revision. No off-node backup is selected for this disposable test deployment. The first-start route is designed by (`dec:observe:first-start-route`); its implementation and installation evidence remain held under (`open:design:secret-integrations`). The secret-home interface establishes protected allocation, generation and import, but exposes no admitted sealing or persistence handoff; it does not by itself implement the supervisor initializer alternative. The selected unprivileged generator requires the protected descriptor handoff below, followed by supervisor sealing and administrator publication; the existing library establishes none of those operations. Required controls are crash-atomic first initialization, exclusive permissions, refusal/recovery of failed partial creation, restart without replacing the established key, and the explicitly retained administrator-access limit. Library-only public result storage may proceed independently; executable credential bootstrap may not.

The shell of (`amend:api:node-package`) declares no credential roles and does not discharge this acquisition or first-initialization hold. Its initializer installation shares the node’s verified tag under (`amend:design:test-installation`); the credential route, parties, store and delivery are owned by (`dec:observe:first-start-route`), (`model:observe:credential-initialization`) and (`rule:observe:credential-store-contract`), with installation premises held under (`open:observe:credential-installation`).

**Decision (First-start credential route)** · `dec:observe:first-start-route` Select a supervisor-owned initialization operation whose repository generator runs under a disposable unprivileged identity, separate from both the instance and store accounts. The intended installation supplies no network, a read-only system view, no writable path and two private named output descriptors per role invocation: password and verifier, each connected directly by a kernel pipe to its own supervisor sealer under administrator custody. Before acquiring entropy or generating either output, the generator requires exactly two descriptors passed through the supervisor's descriptor-passing convention, named password and verifier. It refuses a missing descriptor, a wrong or repeated name, or any additional passed descriptor. Descriptor position or an unnamed extra channel cannot substitute for this closed role roster, since it could send private material to the wrong receiver. The names are public capability metadata; passing them through the convention introduces no secret environment value. Public diagnostics use the two standard streams as a separate channel retained by the supervisor per invocation. This wiring is the operator's intention pending rehearsal under (`open:observe:credential-installation`), not an observed installation property. Source name alone present means the act has not ended; destination name alone present means it has ended, and retry recognizes that state without changes. Both names present on different objects is a collision and refuses with everything unchanged. These readings retain the required synchronization and publication lock; unsupported primitive semantics refuse. Only selection is replaced atomically. Replacing an ending is set aside because it would erase the history needed to distinguish a completed act from a new one. These are operator intentions pending the installation witness, not established filesystem properties.

**Rule (Credential store and delivery contract)** · `rule:observe:credential-store-contract` Under the operator's intended installation, pending rehearsal under (`open:observe:credential-installation`), the administrator owns immutable service definitions, the sealed backing store, its host sealing key, publication and activation. The generator has no store access. Dedicated instance and store accounts are distinct from every build/test account and cannot alter these definitions. Credentials at rest are sealed under the host's own key on that host without hardware binding: protection against copying the store alone does not establish confidentiality from the administrator or from a copy of the whole disk. There is no off-node backup. Delivery is a private memory-backed read-only directory for the unit's lifetime, with files readable by that unit's user alone. The runtime receives neither the backing store nor the owner login; the store account receives neither client password. The schema task receives only its owner role. The intended initial inspection surface exposes unit state and only node/schema-task log lines, not the store log until the verifier sentinel witness is clean; no view exposes credential contents or another unit's private context.

Before reading, each consumer validates the directory capability's provenance, measured owner/mode and access-list contract, read-only lifetime, non-writable ancestors, regular files, absence of symbolic links and alternate link aliases, exact role roster and complete-set marker with its creation/invocation correspondence, bounded lengths, complete formats and end of input. The administrator-owned selection link belongs to the backing-store protocol, not to delivered credential files: the supervisor resolves that single controlled name and validates its complete target and marker before delivery; this grants no exception to consumer refusal of links or aliases in the delivered roster. The supervisor validates the complete backing set before role-specific delivery; a consumer validates only its delivered roster and its association with that selected marker, never receives the other role's password or verifier, and checks plaintext framing separately from the marker's sealed-file lengths. Validate opened descriptors relative to the trusted directory rather than checking a pathname and opening it later. Refuse substitution or changed metadata. The administrator's rehearsal supplies the exact listing against which these checks are implemented; this design does not invent mode values for the delivered mount. Generated password roles each have the exact length specified by (`dec:observe:first-start-route`); connection metadata retains its separately bounded complete format and declared length within the immutable delivery set. Permissive readable files and a writable delivery view are not fallbacks.

No plaintext role password reaches the database server or a provisioning statement. The code cut must supply independent vectors and real-server acceptance of that format before use. The password and salt lengths and provisioning iteration choice are operational profile numbers, not published network quantities; the code cut registers their implementation constants before enabling them.
