# Peer Network · `guide:foundation:overview`

**Section (xchg)** · `sec:foundation:area-xchg` If the interchange implementation fails, canonical byte equality or acceptance can disagree between producers and readers. The package pn-interchange at packages/interchange implements the adopted conventions; its concept (`spec:xchg:concept`), design (`spec:xchg:design`), audit (`rep:xchg:audit`) and commissioning (`rec:xchg:commissioning`) state its contracts and evidence.

**Section (toolchain)** · `sec:foundation:area-toolchain` If the compiler or build profile drifts from policy, the verification entry no longer establishes the intended build conditions. The decision (`rec:toolchain:decision`) fixes the maintained nightly, absence of a minimum compiler and release profile.

## Design areas · `sec:foundation:design-areas`

**Section (design)** · `sec:foundation:area-design` If the implementation design fails, locally correct crates can disagree on public inputs, numerical verdicts or replay and cannot establish the concept as a whole. The design (`spec:design:implementation`) fixes contracts, mechanisms and the evidence required before their claims are implemented.

**Section (lineage)** · `sec:foundation:area-lineage` The decided and unbuilt lineage concept (`spec:lineage:concept`) relates permanent Actor identity, counted signing windows, burns and marker recognition; complete chain evidence and the publication boundary remain with their named admission owners.

**Section (author)** · `sec:foundation:area-author` Identity, token control and signing delegation have different authority. The author-token concept (`spec:author:concept`) explains their relation in an epoch, with qualification, retirement and implementation holds at their existing owners. The lineage concept (`spec:lineage:concept`) preserves this identity and evidence distinction while deciding the designed and unbuilt intersection-window successor; the present admission remains until the identity and development-profile owners admit its replacing cut.

**Section (budget)** · `sec:foundation:area-budget` If resource admission loses its units, scope or consumed work, a refusal can hide expenditure or grant permission twice. The budgeting concept (`spec:budget:concept`) states the decided allocation and work contract, its process-containment stage and the implementations still owed.

**Section (vision)** · `sec:foundation:area-vision` If the implementation concept fails, later packages can satisfy local contracts without delivering a complete, publicly recomputable epoch result. The concept (`spec:vision:concept`) states the purpose, obligations, boundaries, verification and phases of the whole implementation.

**Section (interchange)** · `sec:foundation:area-interchange` If interchange conformance fails, an external reader cannot determine a document's governing theory or acceptance. The conventions (`rec:interchange:decision`) fix that boundary and the implementation (`spec:xchg:concept`) supplies its canonical bytes and acceptance verdicts.

**Section (identity)** · `sec:foundation:area-identity` If identity adjudication fails, a digest can assert a role or assurance its recipe and consumer do not establish. The procedure (`rec:identity:decision`) classifies provenance, comparisons and proposed identities.

**Section (labels)** · `sec:foundation:area-labels` If label resolution fails, citations no longer identify one warranted environment in its declared owner. The calculus (`rec:labels:decision`) fixes the graph and its adoption data.

**Section (kinds)** · `sec:foundation:area-kinds` If kind classification fails, an environment head can claim a genre the declared relation does not recognize. The registry (`rec:kinds:decision`) and its enforced declaration render from one catalogue dataset.

**Section (decomposition)** · `sec:foundation:area-decomposition` If decomposition correspondence fails, crate responsibilities and dependency order lose their connection to the paper's named surfaces. The governing decision is (`rec:decomposition:decision`).

**Section (questions)** · `sec:foundation:area-questions` If question correspondence fails, a provisional reading can be mistaken for a settled implementation contract. The question register (`reg:questions:overview`) preserves the study readings and the maintainers' instructions.

**Section (inventory)** · `sec:foundation:area-inventory` If inventory correspondence fails, a normative statement or constant can disappear from implementation planning without an explicit scope decision. The inventory (`reg:inventory:overview`) preserves proposed homes and unresolved source data.

**Rule (Editing)** · `rule:foundation:editing` Edit document prose in `docs/templates` and repeated facts in `docs/inputs`. From the repository root, run `cargo run -p documents -- generate write`, then `cargo run -p documents -- render write`; review and commit the generated datasets and Markdown with their sources. Both completed writes return zero. For a complete read-only comparison, run `cargo run -p documents -- generate check`, then `cargo run -p documents -- render check` against the same root without intervening edits. Without --output=report each check returns zero when clean or three with differences, with empty stdout and policy-selected bounded terminal error detail on differences. Add --output=report to either mode for its whole report with zero on completion, including differences or changes. A report request is not clean-check evidence. The earlier command spellings are historical baseline evidence and have no aliases. Run (`gate:foundation:verification`) after regeneration, because the reviewed sources and their generated documents must agree. Claim canonicalization, checker preparation and the registration pre-check are not required by the verification entry.

**Gate (Verification)** · `gate:foundation:verification` Run bash ci/check.sh from the repository root in the maintained environment of (`dec:toolchain:compiler`), with Python 3 available for the workspace's compiler wrapper, the entry's member guard and the documents generator. This is the repository’s verification entry: it checks Rust formatting, runs Clippy at the workspace’s strict first-party level, builds the selected workspace code, runs the retained tests, invokes the deployed label linter on the tracked tree under its .linter/ declarations, and checks generation and rendering without writing, because these checks directly support code review and keep the published tree consistent. The caller supplies the deployed linter through LINTER_BIN. The caller states the cgroup's scope through PN_CHECK_CGROUP_SCOPE: own when it started the cgroup or container for this run, shared otherwise; the entry prints unstated when told nothing. The entry fails on a failed required command or unavailable prerequisite and reports each command it ran with its status and wall time; secret values never enter its command lines, environment reports or logs; it does not turn an omitted required test into a pass. A compiler older than (`dec:toolchain:compiler`) allows is reported as a fault of the environment, apart from the tree's result, and the run does not end zero. Retained feature-specific and service-dependent tests use their required configurations and hooks. The entry neither calls ci/gate.sh or ci/precheck.py nor requires the retired graph, claim, tracker, observation-census, performance or discipline batteries. Tracing, privacy and output retain (`rule:observe:spans`), (`rule:observe:privacy`) and (`dec:output:policy`), held by review and focused tests of emitted behaviour.

**Amendment (Verification transition)** · `amend:foundation:verification-transition` The entry of (`gate:foundation:verification`) supersedes requirements to invoke the retained gate, pre-check, build-graph composition, claim and obligation joins, tracker, design pins, observation census, source-discipline batteries and stored performance or workload measurement machinery, except the reproduction receipt and declaration that (`amend:design:replay-roles`) trusts. Their files and recorded results may remain until their owning removal cuts, but their presence does not make them required checks or current evidence. A budget, calibration, roster, census or join stated in (`rec:devperf:decision`), (`rec:buildgraph:decision`) or the claim and harness joins of (`rec:testing:decision`) and (`rec:harness:decision`) describes that retired machinery and is no budget, check or evidence of current work. Stored budgets, calibrations, comparisons and measurement datasets have no replacement in the verification entry. Product contracts, runtime input validation, computational work and capacity limits, executable memory limits, label resolution, and the generation and rendering fixed point retain their force, because retiring verification machinery does not change what a consumer may rely on. Review and package cuts update affected evidence statements before claiming the replacement supported; a green entry is not a retrospective pass of retired checks.

**Rule (Vendored regular-expression engine)** · `rule:vendor:regexml` The engine at vendor/regexml is regexml 0.2.2 from https://github.com/Paligo/regexml, as extended by https://github.com/helping-kaiser/regexml on branch anchored-plus-budget at public commit feddb83dfdacceff2e81e86e7618ca31acccf910. The fork builds on upstream release regexml-v0.2.2 and adds the anchored Regex::is_full_match matcher, an operation budget, Regex::is_full_match_bounded and budget tests; the anchored exposure was proposed upstream as https://github.com/Paligo/regexml/pull/15. It arrived under Apache-2.0 OR MPL-2.0; the repository takes it under MPL-2.0, keeping LICENSE-MPL2, LICENSE-APACHE, COPYRIGHT and CREDITS.txt with the available source. Its files, including the scalar-alias substitution, remain under MPL-2.0 within the larger repository work distributed under AGPL-3.0-only. It does not inherit workspace lints. The copy contains that public commit, the scalar aliases and the local XSD repetition correction described here. Twelve scalar generic arguments use a module-local CodePoint alias for char, declared once in each of src/analyze_string.rs (one), src/op_atom.rs (two), src/re_compiler.rs (three), src/re_matcher.rs (two), src/re_program.rs (three) and src/regex.rs (one), to avoid the repository-prohibited token without changing behaviour. The local correction preserves XSD counts and routes every XSD repetition to the endpoint search in src/re_compiler.rs, keeps that route through sequence optimization in src/op_sequence.rs, and expands each reachable (position, iteration count) state once in src/op_repeat.rs. The unbounded count limit is the subject length plus one; nullable iterations pad the minimum without consuming states. Budgeted calls still count every operand evaluation and pull. Against the public commit, the correction adds one test function in src/op_repeat.rs and updates the existing budget test in tests/test_regexml.rs; snapshots are unchanged. The endpoint search yields distinct endpoints in descending position order, with no promise of upstream's greedy-first preference: replace_all, tokenize and analyze may report a different valid match, and captured spans inside repetitions may come from an explored path rather than the reported derivation. Repository consumers read membership, not captures. XPath keeps the public fork traversal and its incorrect answers for nullable counts and repeated non-empty endpoints. The correction and its evidence are recorded in (`amend:xchg:nullable-counted-repetition`). Replace the vendored copy with the published crate when upstream releases the anchored matcher, operation budget and count-preserving endpoint search.

**Section (compatibility)** · `sec:foundation:area-compatibility` If compatibility policy fails, accidental early interfaces become unsupported promises or assigned interchange laws are weakened by a release policy. The decision (`rec:compatibility:decision`) governs all repository surfaces through (`rule:compatibility:pre-one`).

**Section (storage)** · `sec:foundation:area-storage` If storage fails, a later rule changes an earlier verdict or a partial write masquerades as durable admission. The decision (`rec:storage:decision`) fixes PostgreSQL and effective history separately from deployment operations; stored representations follow (`rule:compatibility:pre-one`).

**Section (observe)** · `sec:foundation:area-observe` If observability fails, work and resource loss become invisible or diagnostics change a binding result. (`rec:observe:decision`) requires labelled spans, metering, metrics and observation independence before the first domain crate; trace and metric names follow (`rule:compatibility:pre-one`).

**Section (testing)** · `sec:foundation:area-testing` If confidence fails, passing suites can conceal unsupported contracts or unchecked invariants. (`rec:testing:decision`) puts review first and states the debug assertions, focused tests and public-record claims that support it, with explicit holds.

**Section (api)** · `sec:foundation:area-api` If the public API fails, callers can confuse a partial query with a published result, lose exact evidence bytes or repeat an uncertain submission. (`rec:api:decision`) separates typed CBOR requests from canonical documents and requires bounded, traced and claim-tested execution.

**Section (devnet)** · `sec:foundation:area-devnet` If development-network contracts fail, grants can be mistaken for destruction, history can count a burn twice, or test evidence can be mistaken for production assurance. (`rec:devnet:decision`) fixes the test-chain realization and bounded faucet.

**Section (harness)** · `sec:foundation:area-harness` If harness discipline fails, a fast substitute can conceal a real-service defect or a client retry can repeat an irreversible effect. (`rec:harness:decision`) fixes test levels, shared suites, functional substitutes and client evidence.

**Section (devperf)** · `sec:foundation:area-devperf` If development performance fails, slow feedback hides defects or noisy timings make correct evidence appear unreliable. (`rec:devperf:decision`) records the retired budgets, findings and registered expensive work under (`amend:foundation:verification-transition`); timing never decided a test or gate verdict.


**Section (intranet)** · `sec:foundation:area-intranet` If host-intranet boundaries fail, private reachability leaks or an operator-provided path is mistaken for implementation-provided transport security. (`rec:intranet:decision`) separates those duties and requires an explicit public case while keeping all connection material secret-owned.

**Section (crypto)** · `sec:foundation:area-crypto` If the cryptographic base fails, shared curve assumptions can hide incompatible implementations or secret-bearing types can bypass the observation boundary. (`rec:crypto:decision`) chooses the base while holding each dependency, recipe and secret-owning integration to its evidence.

## CI claim areas · `sec:foundation:claim-areas`


**Section (design)** · `sec:foundation:claim-area-design` If correspondence claims fail, changed release fields or lost source pins can be accepted without evidence.


**Section (devperf)** · `sec:foundation:claim-area-devperf` If performance-reporting claims fail, durations can change semantic verdicts or missing observations can be invented.


**Section (discipline)** · `sec:foundation:claim-area-discipline` If build-discipline claims fail, a package, test item or output path can evade the workspace checks.


**Section (harness)** · `sec:foundation:claim-area-harness` If harness claims fail, undeclared, missing or misidentified executions can appear as passing evidence.


**Section (hashcitations)** · `sec:foundation:claim-area-hash-citations` If identity-citation claims fail, unresolved identities can enter tracked prose or ordinary words can be refused as identities.


**Section (testing)** · `sec:foundation:claim-area-testing` If evidence-gate claims fail, missing obligations, unowned claims or failed siblings can be hidden by coverage totals.


**Section (buildgraph)** · `sec:foundation:area-buildgraph` If gate composition or file accounting fails, an omitted input or stale result can masquerade as checked evidence. (`rec:buildgraph:decision`) records the retired graph, census and migration slices under (`amend:foundation:verification-transition`); the entry is (`gate:foundation:verification`).
