# Peer Network implementation design · `spec:design:implementation`

## Purpose and scope · `sec:design:purpose`

**Setup (Authority)** · `setup:design:authority` The normative paper edition is network-v0.30.0. This design realizes (`spec:vision:concept`) through public contracts, algorithms and evidence obligations in the sense of (`spec:xchg:design`). Paper labels are exhibited, repository labels are cited, and data-dependent statements follow (`rec:render:decision`). The release and current answer status govern over an older provisional reading in (`reg:questions:overview`).

**Convention (Design boundary)** · `conv:design:scope` The contracts below constrain later domain bites; they do not assert that those crates or their evidence exist. Deployments provide public choices and boundary facts, while later bites choose reviewed dependency versions and concrete storage layouts within these contracts. Consensus, database instance operations, burn realization, guild policy, rewards, bridge, CAN and licence enforcement remain outside (`conv:vision:operations`) and (`conv:vision:terminal-systems`). The implementation owns durable schema and history under (`rec:storage:decision`); its accepted placement is (`proposal:design:storage-placement`). Release support follows (`rule:compatibility:pre-one`). The repository ships its own development deployment profile below that boundary (`rec:devnet:decision`); this does not certify an external burn realization.

**Invariant (Public causes)** · `inv:design:public-causes` A binding operation consumes an immutable input object, an explicit effective declaration and its stated prior-boundary evidence. Its output records the input editions and the premises discharged. No hidden current-price lookup, host cache, previous standing or optional terminal preference may supply a missing input or select a result. Release support follows (`rule:compatibility:pre-one`).

**Decision (Complete cause boundary)** · `dec:design:public-inputs` Represent a proposed boundary as a closed, inspectable public-input object before computation. Check its accepted-act inventory, referenced history, recognized marker, fixed policy, complete accepted burn sets and effective declarations separately from numerical certification; the publication contains the causes and the evidence needed to repeat both checks. Realizes (`req:vision:public-inputs`); grounded in ``post:network:host-contract``, ``prop:deployment:allocation-input-completeness``. Public API carriage follows (`rec:api:decision`).

**Convention (Claim levels)** · `conv:design:claim-levels` Structural validity, certified numerical safety, faithful publication, independent reproduction and operational assurance are separate claims. A passing envelope or matching replay cannot promote one into another. A supported profile states precisely which claims have executed evidence and which remain held (`conv:vision:evidence-ledger`).

Host storage uses the reviewed PostgreSQL client; its optional development-network feature adds pn-wallet, the only Elements RPC integration. Non-development builds omit that edge, and the runtime profile guard remains. The outer node never depends on its client, and replay needs no live node. **Model (Boundary pipeline)** · `model:design:pipeline` Records enter graph formation and dependent-closure validation, then title reconstruction. The epoch compiler freezes the completed ledger, cells, recipients, base allocation and emission; certification selects a rung, the solve encloses its equilibrium, and admission checks the final state. Host publication encodes that state and its causes. Replay starts from those causes and reconstructs each stage. Readouts consume the immutable final snapshot. Verification consumes public surfaces as a development-only leaf (`dec:decomposition:crates`). Public API carriage follows (`rec:api:decision`).

**Invariant (Stage ownership)** · `inv:design:stage-ownership` Records own carriers and validation of their local invariants; graph owns structural meaning; epoch owns binding computation; host owns encoding; replay owns reconstruction and comparison. An upstream crate never calls a downstream crate. Optional raw payloads are passed to host as explicitly nonbinding data, so host has no dependency on the readout engine. The accepted storage adapter gives host database I/O while records retains pure validation; computation never reads a hidden database state (`sig:design:storage`). Public API carriage follows (`rec:api:decision`).

**Model (State progression)** · `model:design:state-progression` An unchecked proposal becomes a structurally validated candidate, then a frozen compiled epoch, then a certified equilibrium, then an admitted final state. Each transition returns its evidence or a typed failure. A candidate is never exposed as accepted merely because an intermediate stage succeeded; only the admitted object can authorize a host publication labelled accepted. Observation follows (`rec:observe:decision`).

**Invariant (Stable references)** · `inv:design:stable-references` Cross-crate references name structural objects and effective editions, never addresses in mutable storage. Canonical sorting is a presentation rule distinct from authoritative act positions. Collection iteration order cannot break title ties, choose a recipient or choose a rung. Acceleration indexes may be rebuilt from the immutable input without changing its meaning. A petgraph NodeIndex or EdgeIndex is a storage position within one graph value: it may travel with that value across a crate boundary, but never serves as cross-crate structural identity. Structural identifiers live in the weights. StableGraph preserves unrelated live indices during removal, not the identity of a deleted slot; discard removed handles and re-resolve structural identifiers after rebuilding or mutation. Iteration reflects insertion and storage history, not mathematical priority: directed adjacency iteration is reverse edge-insertion order, and reused slots are not chronological order. Binding consumers enumerate by authoritative positions and structural roles, never by incidental iterator order (`alg:design:formation`).

## Records and declarations · `sec:design:records`

**Signature (Records)** · `sig:design:records` pn-records offers validate-record, resolve-public-reference, assemble-boundary-inputs and select-effective-declaration. Constructors preserve authored identity, projection completeness, units and vintage; they refuse ambiguous duplicate identities, unresolved required references and invalid local representations. They do not certify formation, destruction of burn backing or a standing result. The same carriers are usable by host and replay without a codec dependency. Observation follows (`rec:observe:decision`).

**Model (Accepted act)** · `model:design:accepted-act` An act carries its structural identifier, author, family, structural body, mandatory and removable projections, immutable protocol references, authentication evidence, finalization epoch, position within that epoch and retained host-attached logical time. Edge identifiers derive from the parent act and the declared binary or A/T role. The act owns its full projection set; co-legs cannot appear as independent accounting units. Tombstonable dependency projections and non-tombstonable protocol references remain distinct fields. In the petgraph projection value, node weights retain the structural node identifier and endpoint sort, while edge weights retain the structural edge identifier, parent act identifier, projection role, epoch-qualified published position, retained logical time and removal status. Mandatory protocol references remain distinguishable from removable dependencies; parallel edges with distinct structural identifiers remain distinct.

**Decision (Whole-act identity)** · `dec:design:complete-acts` Validate and retain every accepted authored act before folding. Keep the member identities of every fold cell as witnesses, but maintain action counts and debit increments from the complete authored-act inventory. A cancelled stance, hostile act, zero coefficient or home recipient never removes that act from accounting. Realizes (`req:vision:complete-acts`); grounded in ``def:graph:act-identifier``, ``def:graph:act-edge-projection``, ``post:epoch:universal-act-weighing``.

**Model (Burn boundary)** · `model:design:burn` The burn carrier contains the amount map sampled for every read address, opaque address space, bootstrap capacity bound and unit-cost projection. The unit cost is positive in its declared external denomination per burn unit, with applicable terms; no bound of one follows from destruction provenance. A companion evidence record carries settlement depth and the finality assumptions under which no history containing a settlement boundary is replaced beyond that depth; an amount sampled at or below it equals its pinned amount (``cond:comparator:burn-settlement-depth``). It also carries provenance, separate recording-event costs with their denomination and terms, and either the applicable operator bound with proof or an explained absence of an accruing operational role. An empty pre-opening acquisition interval requires a published zero bootstrap bound and explanation, not a cap on later burns. Both carry their effective edition and boundary sample convention; an absent required disclosure is a publication failure even when no arithmetic formula reads it (`dec:decomposition:burn`). Release support follows (`rule:compatibility:pre-one`). The development adapter supplies the test map, run-qualified opaque addresses, constants and chain disclosures under (`rule:devnet:burn-map`) and (`rule:devnet:settlement`); retain its declared test-unit outlay, fixed-supply release schedule and explicit non-production assurance status (`cav:devnet:assurance`). The development address remains permanent while new target-committed destruction events accumulate under (`amend:devnet:burn-targets`); an outpoint identifies evidence, not a mutable actor binding. Recorded burn amounts cannot move or pool across addresses; aggregated evidence must preserve every original amount and attribution without duplicate contribution. This restriction does not make standing non-transferable or prevent its concentration under alternative funded address histories. Downward revision of an intermediate publication is permitted no lower than the last settled pin when an alternative history omits a not-yet-final boundary (``cond:comparator:burn-non-transferability``, ``cond:comparator:burn-revision-floor``). The sampled map and its increment are derived by (`alg:design:burn-snapshot`) only after (`rule:design:marker-recognition`); an RPC balance or a reader observation cannot replace the accepted-set evidence.

**Decision (Imported amount and audit evidence)** · `dec:design:burn-boundary` Keep the mathematical burn interface separate from evidence about its realization. Verify marker recognition, accepted-set completeness, single-count sample coverage and declared units at the boundary, carry required disclosures unmodified, and report the assurance supplied by the deployment without claiming that a numeric computation proves destruction. The declared development counterpart and its economic-assurance limitation are (`rec:devnet:decision`) and (`cav:devnet:assurance`). Realizes (`req:vision:burn-boundary`); grounded in ``def:comparator:burn-interface``, ``subsec:deployment:realization-obligations``, ``post:comparator:marker-bound-settlement``, ``cond:comparator:marker-lineage-succession``, ``cond:comparator:marker-network-acceptance``, ``cond:comparator:marker-causal-dependence``, ``cond:comparator:marker-single-count``, ``def:comparator:marker-burn-snapshot``, ``eq:comparator:marker-burn-snapshot``, ``prop:comparator:marker-settlement-consistency``, ``cond:comparator:burn-unit-cost-projection``, ``cond:comparator:burn-non-transferability``, ``cond:comparator:burn-settlement-amount``, ``cond:comparator:burn-revision-floor``, ``cond:comparator:burn-bootstrap-capacity``, ``cond:comparator:burn-operator-audit-bound``.

**Rule (Marker recognition)** · `rule:design:marker-recognition` Before deriving burn, pn-host checks the published pre-genesis policy and its fixed identity and edition, open placement and cadence, initial marker with index zero, no predecessor and empty accepted set and snapshot, unique immediate succession and growing lineage under ``cond:comparator:marker-lineage-succession``. Marker identity fixes predecessor, lineage and public interpretation; its existence depends on the whole lineage and predecessor, so copying contents into a history missing either cannot preserve that marker (``cond:comparator:marker-causal-dependence``). Verify the published settlement depth and finality assumptions for the history containing the settlement boundary, including marker, lineage and interpretation; epoch reads use a declared stability buffer strictly exceeding that depth under ``post:epoch:final-edge-set``. Recover each complete finite accepted set from the encoding chosen by the marker policy: a complete list, a commitment with a uniquely verifiable public opening, or another encoding satisfying the same complete-recovery and member-verification conditions under ``post:epoch:final-edge-set``. Check the set under the policy, containing predecessor acceptance and contained in current lineage; verify destruction, nonnegative amount and original address for every member, including consistency across aliases (``cond:comparator:marker-network-acceptance``). Missing or ambiguous public openings prevent recognition; invalid members, regressed acceptance and out-of-lineage records are refused, never repaired by clipping, enlargement or omission. Bounds compare successors within one history, not across alternative histories. Record order suffices only for the declared whole-prefix, accept-all special case. This checks realization evidence without proving external finality; missing evidence prevents readiness, and malformed evidence names its field and violated rule under (`model:design:failures`).

**Algorithm (Accepted burn snapshot)** · `alg:design:burn-snapshot` Starting from the empty marker snapshot, recover the complete accepted set from the policy-selected encoding and verified public openings under (`rule:design:marker-recognition`), then enumerate its records and verify their underlying destruction identities, amounts and original addresses. At each recognized marker, subtract the set of destruction identities already represented at its predecessor, then sum only the newly represented amounts by address. A record already in earlier lineage may contribute on first acceptance at the accepting marker; further references to the same destruction never contribute again, even under another address (``cond:comparator:marker-single-count``, ``def:comparator:marker-burn-snapshot``, ``eq:comparator:marker-burn-snapshot``). Return both the gross snapshot and its increment with their complete witnesses. Between markers, retain the last settled snapshot; neither a visible burn nor lineage inclusion alone justifies an intermediate increase (``cond:comparator:burn-conservative-publication``). The same final marker and fixed policy determine the same result; nonnegative increments concern gross amounts along that history, not residual balances after charges (``prop:comparator:marker-settlement-consistency``). Epoch compilation consumes this result once with the writing-epoch debit vintage. No acceptance deadline, compulsory acceptance or eventual marker production is inferred. Bite 2 introduces the burn-data, marker-policy, lineage and accepted-set carriers and their validation in pn-records. Bite 5 implements snapshot and first-accepted increment derivation in pn-epoch to feed the ledger. The host recognizes external evidence and replay repeats the checks and derivation from the disclosed closure without a live node.

**Model (Ledger records)** · `model:design:ledger` Each anchored Actor has a settled cumulative burn amount, nonnegative final residual balance, positive action count and a history of charged increments indexed by effective epoch. A proposed increment names the charged value in force and its representation edition. Residual balance is derived from settled burn and consummated debit history, with the proposed epoch increments applied once; published balances are checked outputs, not independent replacement inputs. Release support follows (`rule:compatibility:pre-one`). Development grants are operational transfers only; only qualified destruction accepted at the recognized marker can supply a later test burn sample (`rule:design:devnet-history`). The gross amount increases only when the common recognized marker first accepts a destruction; older lineage burns may contribute at that accepting marker, even with no authored act, and repeated aliases contribute nothing. Residual balances need not be monotone after debits (``def:epoch:proposed-final-act-state``).

**Model (Declarations)** · `model:design:declarations` An effective declaration identifies the formula edition, constant definitions, permitted overrides, announcement and effective boundaries, domain profiles, numerical procedure, authentication realization and publication profile. The structural tier declares the numeraire and fixed safety-wall floor before the first epoch; the controller edition, initialization, constants and comparison procedure are public. Preserve the in-force wall and price, completed width, accepted rung, next proposal and delivered wall with their boundary references. Exact literals, computed quantities and illustrative displays have distinct roles. Resolution at an old boundary returns the old declaration; a floor change is a public structural change with regenerated evidence, never an epoch override. Durable resolution follows (`model:storage:scd2`) and (`rule:design:as-of`). Release support follows (`rule:compatibility:pre-one`). The deployment also publishes its marker policy identity and edition, open placement and cadence before genesis. The policy is immutable for that marker sequence; later SCD2 declarations cannot reinterpret a recognized marker or erase predecessor acceptance (``post:comparator:marker-bound-settlement``).

**Decision (Effective formulas and constants)** · `dec:design:constants` Select declarations by their published effective boundary, reject locked overrides and missing lead, and retain reproduction evidence for computed constants. Generate defaults only through the read-only correspondence gate of the constants bite; compare defining formulas and exact literals separately from certified computed values and displayed rounding. Realizes (`req:vision:constants`); grounded in ``subsec:deployment:transparency-of-protocol-formulas``, ``rem:verification:numerical-rounding``. Release support follows (`rule:compatibility:pre-one`).

**Invariant (Charged value)** · `inv:design:charged-value` The reduced wall is primary and the charged price is that wall multiplied by the declared positive numeraire; they are one coordinate pair, never independent settings (``def:epoch:safety-wall``). Debit, own-balance solvency, the individual safety comparison, emission and capacity read the same published price and its reduced image. The deployment certifies the labelled conditions of ``def:epoch:safety-threshold`` for the actual representable charge, including the exact structural-floor comparison; rounding a target does not discharge them. Neither replay nor a price change may reprice a consummated vintage (`dec:decomposition:numbers`).

**Decision (Preserved charges)** · `dec:design:ledger-vintages` The initial supported ledger profile uses exact finite rational charged values with explicit units and certified wall, floor and charged-value evidence. Preserve those exact values and their vintages. A profile admitting other exact real descriptions must supply a total interpretation, certified enclosure evaluator and equality-witness contract before support is claimed; a rounded display is never such a description. Realizes (`req:vision:ledger-vintages`); grounded in ``post:epoch:act-debit``, ``def:epoch:safety-threshold``. Release support follows (`rule:compatibility:pre-one`).

## Durable storage and historical resolution · `sec:design:storage`

**Model (Durable history)** · `model:design:storage-history` PostgreSQL stores the public causes and durable results under (`rec:storage:decision`). PostgreSQL is a trusted deployment component under (`amend:storage:server-trust`); library checks validate its returned deployment state, while instance-private settings stay secret-owned by construction. Rules and declarations use SCD2 rows; accepted act bodies remain immutable and versioned acceptance or removal facts retain their authoritative positions. Ledger charges retain their consummated vintages as immutable debit evidence, while derived balances are versioned by effective epoch. Epoch results are immutable admitted snapshots bound to their accepted input set, declaration versions and evidence; a corrected later result is distinct and never overwrites an earlier verdict. This maps (`model:design:accepted-act`), (`model:design:ledger`) and (`model:design:declarations`) onto effective history, not an alternative mathematical source. A rebuild starts from publicly available inputs, resolves their declarations and reconstructs public derived state under (`rule:compatibility:pre-one`); the deployment re-supplies instance-private settings through secret bootstrap under (`conv:storage:ownership`). Persist marker identity, predecessor, policy identity and fixed edition, lineage and interpretation evidence, the policy-selected accepted-set representation and its public verification evidence, and distinct destruction identities with their address and amount. Retain the lists or uniquely verifiable public openings needed for complete recovery and verification against the policy and both acceptance bounds; a commitment without its recoverable opening is insufficient. Bind each admitted epoch atomically to that immutable marker snapshot and predecessor state; SCD2 records recognition and fault history without changing the original evidence. Later observation or a policy edition from another sequence cannot alter an old snapshot. Under ``cond:deployment:canonical-encoding`` and ``cond:deployment:canonical-replay``, retain the exact canonical inputs and outputs, effective profile and procedure edition, centres and enclosure endpoints, and every attempted rung verdict and refinement record needed to reproduce publication. A later decoder or recomputation cannot replace the original bytes; declared numerical allowances never excuse a different PASS, FAIL or INDECISIVE verdict. Representation and first production follow (`amend:storage:artifact-representation`) and (`amend:decomposition:storage-representation`): pre-publication inputs are typed immutable values with effective editions, stored as deterministic canonical projections with opaque evidence preserved; byte-exact published packages and certifications begin at bite 8. Where a family has no validating carrier, its caller’s interchange value supplies that projection; storage grants it no domain validity, and its carrier must validate opaque payloads before a consumer relies on them.

**Rule (As-of resolution)** · `rule:design:as-of` Resolve a key at boundary b by its unique interval with opening at or before b and closing strictly after b, or no closing boundary. The key's declared lifetime distinguishes absence before creation from a missing required version; a withdrawal is an explicit absence-valued successor. All inputs for one candidate come from one consistent snapshot and carry their effective version identities. No newest-row fallback is permitted. Reject gaps, overlaps, ambiguous references and unauthorized retroactive changes; a future-effective version must leave every earlier boundary verdict unchanged (`rule:storage:as-of`). History correctness within the supported representation is required independently of cross-release support (`rule:compatibility:pre-one`).

**Signature (Storage)** · `sig:design:storage` Under accepted (`proposal:design:storage-placement`), pn-host offers open-store, load-boundary, append-effective-successor and commit-admitted-epoch. The whole connection-only JSON configuration is secret-owned from read through connection establishment under (`rule:storage:configuration`) and (`inv:observe:secret-boundary`); declarations and other settings come from the database or public inputs. pn-records validates carriers and local history invariants without database I/O; host owns transactions and resolves a complete immutable boundary input before calling graph or epoch. Append-effective-successor commits the immutable closure fact and successor together, with serialized conflict handling. Commit-admitted-epoch exposes its input references, debit evidence and result together or none; retry must recognize the same structural event without applying a debit twice. Storage failures carry no mathematical verdict, and incomplete writes never authorize publication. Replay requires only the public package and disclosed history, not access to the host database. Stored representations follow (`rule:compatibility:pre-one`). Observation follows (`rec:observe:decision`). Development burn and grant history obeys (`rule:design:devnet-history`), with no cross-system atomicity claim.

Inject failure between closure and successor and before commit, verify rollback and retry, and confirm no partial admitted result or duplicate debit appears. Owning host tests run from bite 2 under accepted (`proposal:design:storage-placement`); later bites add ledger and epoch cases as those contracts land, and pn-verification consumes the public surface for integrated evidence. ## Formation, geometry and title · `sec:design:graph`

**Signature (Graph)** · `sig:design:graph` pn-graph offers validate-formation, project-complete-act, partition-dependencies, evaluate-geometry, recognize-settlements and fold-title. Outputs include checked projection witnesses, structural folds, geometry enclosures and boundary-indexed title evidence. It guarantees the family census, identifier algebra, endpoint typing and reference rules, while leaving standing allocation to epoch and authentication realization to the declared adapter. The graph substrate is petgraph on release line 0.8, with reviewed release 0.8.3, licensed MIT OR Apache-2.0. Bite 3 declares the dependency once in the workspace manifest at the latest available 0.8 release, retaining default features std, graphmap, stable_graph, matrix_graph and enabling serde-1; pn-graph inherits that declaration and the lockfile records its resolution. A later release line requires its own reviewed change. Public contracts use the petgraph types below directly, with no wrapper type around the graph. pn-graph validates the domain obligations, including complete projections, on inputs and outputs; arbitrary mutation or serde deserialization does not preserve a previous validation result and requires revalidation before binding use. Release support follows (`rule:compatibility:pre-one`).

| Directed complete projections and their dependency roles, including removable projections and parallel edges | petgraph::stable_graph::StableDiGraph (directed StableGraph) | StableGraph preserves unrelated node and edge indices on removal and supports parallel edges; a removed slot is not a permanent identity and may be reused. |

Each exact rational degree is in [0, 1]; the pair’s interpretation and severity remain outside admission under network-v0.30.0, ``def:content:license-qualifiers`` and ``prop:content:closure-exclusion``. The obsolete license-namespace protocol-reference encoding refuses even when a lookup entry exists. Protocol references to acts and edges must resolve. Accept and Ratify carry typed non-removable settlement metadata in their structural bodies: settles and accepts retain exact act identities; earlier wrong-family or different-Bid targets are admitted and fail recognition clause (ii), rather than formation. **Rule (Comparison)** · `rule:design:numeric-comparison` For a required non-strict x greater-than-or-equal-to y comparison, PASS requires a lower bound of x at least the upper bound of y, and FAIL requires an upper bound of x below the lower bound of y. Strict comparisons use the corresponding strict separation; a certificate must prove c strictly below unity before residual division. Observation follows (`rec:observe:decision`).

**Rule (Equality witnesses)** · `rule:design:equality` Equality is decidable for normalized rationals and identical canonical exact expressions within their declared interpretation. Observation follows (`rec:observe:decision`).

**Rule (Deterministic refinement)** · `rule:design:refinement` The numerical declaration fixes the starting precision, refinement sequence, operation and iteration caps, expression evaluation order, stopping predicates and output endpoint grid. The reference solve starts from the declaration's hull point and records every binding stopping decision. nrz-scalar supports binary32 and binary64 only; nrz-accuracy can promote from the former to the latter, with no further promotion. Widening an existing enclosure alone supplies no new accuracy. ## Verdicts and failures · `sec:design:verdicts`

**Model (Verdict algebra)** · `model:design:verdicts` A checked proposition returns PASS with premises and evidence, FAIL with a proved countercondition, or INDECISIVE with the unresolved comparison and exhausted declared refinement. **Model (Operational failures)** · `model:design:failures` Malformed input reports the field and violated representation rule; unsupported reports an unknown profile, operation, witness or preflight size; resource exhaustion reports the stage, declared limit and progress; interruption and internal invariant failure report no mathematical verdict. **Rule (Cross-crate propagation)** · `rule:design:failure-propagation` Preserve the originating category and attribution when crossing a crate boundary.
