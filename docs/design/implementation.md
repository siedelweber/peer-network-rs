# Peer Network implementation design · `spec:design:implementation`

## Purpose and scope · `sec:design:purpose`

**Setup (Authority)** · `setup:design:authority` The normative paper edition is network-v0.25.1. This design realizes (`spec:vision:concept`) through public contracts, algorithms and evidence obligations in the sense of (`spec:xchg:design`). Paper labels are exhibited, repository labels are cited, and data-dependent statements follow (`rec:render:decision`). The release and current answer status govern over an older provisional reading in (`reg:questions:overview`). Release support follows (`rule:compatibility:pre-one`).

**Convention (Design boundary)** · `conv:design:scope` The contracts below constrain later domain bites; they do not assert that those crates or their evidence exist. Deployments provide public choices and boundary facts, while later bites choose reviewed dependency versions and concrete storage layouts within these contracts. Consensus, database instance operations, burn realization, guild policy, rewards, bridge, CAN and licence enforcement remain outside (`conv:vision:operations`) and (`conv:vision:terminal-systems`). The implementation owns durable schema and history under (`rec:storage:decision`); its proposed placement is (`proposal:design:storage-placement`). Release support follows (`rule:compatibility:pre-one`).

**Invariant (Public causes)** · `inv:design:public-causes` A binding operation consumes an immutable input object, an explicit effective declaration and its stated prior-boundary evidence. Its output records the input editions and the premises discharged. No hidden current-price lookup, host cache, previous standing or optional terminal preference may supply a missing input or select a result. Release support follows (`rule:compatibility:pre-one`).

**Decision (Complete cause boundary)** · `dec:design:public-inputs` Represent a proposed boundary as a closed, inspectable public-input object before computation. Check its accepted-act inventory, referenced history, settled burn samples and effective declarations separately from numerical certification; the publication contains the causes and the evidence needed to repeat both checks. Realizes (`req:vision:public-inputs`); grounded in ``post:network:host-contract``, ``prop:deployment:allocation-input-completeness``. Release support follows (`rule:compatibility:pre-one`). Observation follows (`rec:observe:decision`).

**Convention (Claim levels)** · `conv:design:claim-levels` Structural validity, certified numerical safety, faithful publication, independent reproduction and operational assurance are separate claims. A passing envelope or matching replay cannot promote one into another. A supported profile states precisely which claims have executed evidence and which remain held (`conv:vision:evidence-ledger`). Release support follows (`rule:compatibility:pre-one`).

## Architecture and data flow · `sec:design:architecture`

**Model (Crate graph)** · `model:design:crates` The adopted domain graph contains 7 crates, with the direct prerequisites below taken from (`conv:decomposition:dependencies`). Every domain name must occur in the concept responsibility map; the infrastructure column includes the accepted amendment (`amend:decomposition:publication`). The proposed PostgreSQL adapter and its earlier host slice are separate from this adopted graph (`proposal:design:storage-placement`); no unaccepted dependency is included in the table. Release support follows (`rule:compatibility:pre-one`).

| Crate | Responsibility | Direct domain prerequisites | Direct infrastructure prerequisites |
| --- | --- | --- | --- |
| pn-records | Immutable public inputs: identities, acts, ledger/burn data and declared constants | None | None |
| pn-graph | Structural formation, shared graph algebra and title folds | pn-records | None |
| pn-epoch | Compile and certify one final epoch state and its admission result | pn-records, pn-graph | None |
| pn-readouts | Expose published standing/title and optional exact raw views to terminal consumers | pn-records, pn-graph, pn-epoch | None |
| pn-host | Encode the complete seven-part public package | pn-records, pn-graph, pn-epoch | pn-interchange |
| pn-replay | Reconstruct and compare the binding package from public inputs | pn-records, pn-graph, pn-epoch, pn-host | None |
| pn-verification | Maintain labelled integrated fixtures and independent public-surface checks | pn-records, pn-graph, pn-epoch, pn-readouts, pn-host, pn-replay | None |

**Model (Boundary pipeline)** · `model:design:pipeline` Records enter graph formation and dependent-closure validation, then title reconstruction. The epoch compiler freezes the completed ledger, cells, recipients, base allocation and emission; certification selects a rung, the solve encloses its equilibrium, and admission checks the final state. Host publication encodes that state and its causes. Replay starts from those causes and reconstructs each stage. Readouts consume the immutable final snapshot. Verification consumes public surfaces as a development-only leaf (`dec:decomposition:crates`). Release support follows (`rule:compatibility:pre-one`).

**Invariant (Stage ownership)** · `inv:design:stage-ownership` Records own carriers and validation of their local invariants; graph owns structural meaning; epoch owns binding computation; host owns encoding; replay owns reconstruction and comparison. An upstream crate never calls a downstream crate. Optional raw payloads are passed to host as explicitly nonbinding data, so host has no dependency on the readout engine. The proposed storage adapter gives host database I/O while records retains pure validation; computation never reads a hidden database state (`sig:design:storage`). Release support follows (`rule:compatibility:pre-one`).

**Model (State progression)** · `model:design:state-progression` An unchecked proposal becomes a structurally validated candidate, then a frozen compiled epoch, then a certified equilibrium, then an admitted final state. Each transition returns its evidence or a typed failure. A candidate is never exposed as accepted merely because an intermediate stage succeeded; only the admitted object can authorize a host publication labelled accepted. Observation follows (`rec:observe:decision`).

**Invariant (Stable references)** · `inv:design:stable-references` Cross-crate references name structural objects and effective editions, never addresses in mutable storage. Canonical sorting is a presentation rule distinct from authoritative act positions. Collection iteration order cannot break title ties, choose a recipient or choose a rung. Acceleration indexes may be rebuilt from the immutable input without changing its meaning. A petgraph NodeIndex or EdgeIndex is a storage position within one graph value: it may travel with that value across a crate boundary, but never serves as cross-crate structural identity. Structural identifiers live in the weights. StableGraph preserves unrelated live indices during removal, not the identity of a deleted slot; discard removed handles and re-resolve structural identifiers after rebuilding or mutation. Iteration reflects insertion and storage history, not mathematical priority: directed adjacency iteration is reverse edge-insertion order, and reused slots are not chronological order. Binding consumers enumerate by authoritative positions and structural roles, never by incidental iterator order (`alg:design:formation`). Release support follows (`rule:compatibility:pre-one`).

## Records and declarations · `sec:design:records`

**Signature (Records)** · `sig:design:records` pn-records offers validate-record, resolve-public-reference, assemble-boundary-inputs and select-effective-declaration. Constructors preserve authored identity, projection completeness, units and vintage; they refuse ambiguous duplicate identities, unresolved required references and invalid local representations. They do not certify formation, destruction of burn backing or a standing result. The same carriers are usable by host and replay without a codec dependency. Observation follows (`rec:observe:decision`).

**Model (Accepted act)** · `model:design:accepted-act` An act carries its structural identifier, author, family, structural body, mandatory and removable projections, immutable protocol references, authentication evidence, finalization epoch and authoritative position. Edge identifiers derive from the parent act and the declared binary or A/T role. The act owns its full projection set; co-legs cannot appear as independent accounting units. Tombstonable dependency projections and non-tombstonable protocol references remain distinct fields. In the petgraph projection value, node weights retain the structural node identifier and endpoint sort, while edge weights retain the structural edge identifier, parent act identifier, projection role, authoritative position and removal status. Mandatory protocol references remain distinguishable from removable dependencies; parallel edges with distinct structural identifiers remain distinct.

**Decision (Whole-act identity)** · `dec:design:complete-acts` Validate and retain every accepted authored act before folding. Keep the member identities of every fold cell as witnesses, but maintain action counts and debit increments from the complete authored-act inventory. A cancelled stance, hostile act, zero coefficient or home recipient never removes that act from accounting. Realizes (`req:vision:complete-acts`); grounded in ``def:graph:act-identifier``, ``def:graph:act-edge-projection``, ``post:epoch:universal-act-weighing``. Release support follows (`rule:compatibility:pre-one`). Observation follows (`rec:observe:decision`).

**Model (Burn boundary)** · `model:design:burn` The burn carrier contains the value map sampled for every read address, opaque address space, bootstrap capacity bound and unit-cost projection. A companion evidence record carries settlement depth, provenance and the conditional operator bound with its proof when applicable. Both carry their effective edition and boundary sample convention; an absent required disclosure is a publication failure even when no arithmetic formula reads it (`dec:decomposition:burn`). Release support follows (`rule:compatibility:pre-one`). Observation follows (`rec:observe:decision`).

**Decision (Imported value and audit evidence)** · `dec:design:burn-boundary` Keep the mathematical burn interface separate from evidence about its realization. Verify sample coverage and declared units at the boundary, carry required disclosures unmodified, and report the assurance supplied by the deployment without claiming that a numeric computation proves destruction. Realizes (`req:vision:burn-boundary`); grounded in ``def:comparator:burn-interface``, ``subsec:deployment:realization-obligations``. Release support follows (`rule:compatibility:pre-one`). Observation follows (`rec:observe:decision`).

**Model (Ledger records)** · `model:design:ledger` Each anchored Actor has a settled cumulative burn value, nonnegative final residual balance, positive action count and a history of charged increments indexed by effective epoch. A proposed increment names the charged value in force and its representation edition. Residual balance is derived from settled burn and consummated debit history, with the proposed epoch increments applied once; published balances are checked outputs, not independent replacement inputs. Release support follows (`rule:compatibility:pre-one`).

**Model (Declarations)** · `model:design:declarations` An effective declaration identifies the formula edition, constant definitions, permitted overrides, announcement and effective boundaries, domain profiles, numerical procedure, authentication realization, publication profile and calibration procedure. Exact literals, computed quantities and illustrative displays have distinct roles. Resolution at an old boundary must return the old declaration, even when a newer one is available. Durable resolution uses the SCD2 interval and atomic-succession contract (`model:storage:scd2`), with explicit effective version references (`rule:design:as-of`). Release support follows (`rule:compatibility:pre-one`).

**Decision (Effective formulas and constants)** · `dec:design:constants` Select declarations by their published effective boundary, reject locked overrides and missing lead, and retain reproduction evidence for computed constants. Generate defaults only through the read-only correspondence gate of the constants bite; compare defining formulas and exact literals separately from certified computed values and displayed rounding. Realizes (`req:vision:constants`); grounded in ``subsec:deployment:transparency-of-protocol-formulas``, ``rem:verification:numerical-rounding``. Release support follows (`rule:compatibility:pre-one`). Observation follows (`rec:observe:decision`).

**Invariant (Charged value)** · `inv:design:charged-value` The deployment publishes a single charged value for an epoch. Debit, W1, the safety floor, emission and capacity read that same value. The defining calibration formula specifies its target; certification must establish the required conditions for the actual charge. Neither replay nor a price change may reprice a consummated vintage (`dec:decomposition:numbers`).

**Decision (Preserved charges)** · `dec:design:ledger-vintages` The initial supported ledger profile uses exact finite rational charged values with explicit units and certified calibration evidence. Preserve those exact values and their vintages. A profile admitting other exact real descriptions must supply a total interpretation, certified enclosure evaluator and equality-witness contract before support is claimed; a rounded display is never such a description. Realizes (`req:vision:ledger-vintages`); grounded in ``post:epoch:act-debit``, ``def:epoch:safety-threshold``. Release support follows (`rule:compatibility:pre-one`). Observation follows (`rec:observe:decision`).

## Durable storage and historical resolution · `sec:design:storage`

**Model (Durable history)** · `model:design:storage-history` PostgreSQL stores the public causes and durable results under (`rec:storage:decision`). Rules and declarations use SCD2 rows; accepted act bodies remain immutable and versioned acceptance or removal facts retain their authoritative positions. Ledger charges retain their consummated vintages as immutable debit evidence, while derived balances are versioned by effective epoch. Epoch results are immutable admitted snapshots bound to their accepted input set, declaration versions and evidence; a corrected later result is distinct and never overwrites an earlier verdict. This maps (`model:design:accepted-act`), (`model:design:ledger`) and (`model:design:declarations`) onto effective history, not an alternative mathematical source. A rebuild starts from publicly available inputs, resolves their declarations and reconstructs derived state under (`rule:compatibility:pre-one`). Observation follows (`rec:observe:decision`).

**Rule (As-of resolution)** · `rule:design:as-of` Resolve a key at boundary b by its unique interval with opening at or before b and closing strictly after b, or no closing boundary. The key's declared lifetime distinguishes absence before creation from a missing required version; a withdrawal is an explicit absence-valued successor. All inputs for one candidate come from one consistent snapshot and carry their effective version identities. No newest-row fallback is permitted. Reject gaps, overlaps, ambiguous references and unauthorized retroactive changes; a future-effective version must leave every earlier boundary verdict unchanged (`rule:storage:as-of`). History correctness within the supported representation is required independently of cross-release support (`rule:compatibility:pre-one`). Observation follows (`rec:observe:decision`).

**Signature (Storage)** · `sig:design:storage` Subject to (`proposal:design:storage-placement`), pn-host offers open-store, load-boundary, append-effective-successor and commit-admitted-epoch. The whole connection-only JSON configuration is secret-owned from read through connection establishment under (`rule:storage:configuration`) and (`inv:observe:secret-boundary`); declarations and other settings come from the database or public inputs. pn-records validates carriers and local history invariants without database I/O; host owns transactions and resolves a complete immutable boundary input before calling graph or epoch. Append-effective-successor commits the immutable closure fact and successor together, with serialized conflict handling. Commit-admitted-epoch exposes its input references, debit evidence and result together or none; retry must recognize the same structural event without applying a debit twice. Storage failures carry no mathematical verdict, and incomplete writes never authorize publication. Replay requires only the public package and disclosed history, not access to the host database. Stored representations follow (`rule:compatibility:pre-one`). Observation follows (`rec:observe:decision`).

**Proposal (Storage placement and first slice)** · `proposal:design:storage-placement` Proposed for repository-owner review before storage implementation: place the PostgreSQL adapter in pn-host, introduce its storage-only slice during bite 2 alongside numeric representation and effective declarations, and add a reviewed PostgreSQL client as an infrastructure dependency of pn-host. This extends the content of (`dec:decomposition:bites`) and the dependency list of (`conv:decomposition:dependencies`); it does not change either record here. Host already owns external effects and has a records dependency, so this placement avoids a new domain crate or database dependencies in graph and epoch. The earlier slice has no dependency on not-yet-implemented computation; bite 8 completes host publication. The adopted bite order and domain boundaries remain intact, while database invariants receive real-instance tests from their first implementation. The owner must accept this placement or record an alternative before the affected slice; the PostgreSQL and compatibility decisions themselves are accepted (`rec:storage:decision`), (`rule:compatibility:pre-one`).

**Verification (Storage history)** · `verif:design:storage-history` From the first storage slice, the gate requires a real PostgreSQL instance on the latest published beta under (`dec:storage:postgresql`), logging its server version and refusing a missing or unsupported instance. Exercise as-of queries at opening and closing boundaries, before creation and after explicit withdrawal; reject gaps and overlaps for a live key. Concurrent successor attempts must serialize to one valid history. Inject failure between closure and successor and before commit, verify rollback and retry, and confirm no partial admitted result or duplicate debit appears. Append a later-effective rule and compare an earlier reconstructed verdict and its selected declaration identities unchanged. Rebuild from the same public inputs and compare logical histories and results, not physical row order. Owning host tests run from bite 2 if (`proposal:design:storage-placement`) is accepted; later bites add ledger and epoch cases as those contracts land, and pn-verification consumes the public surface for integrated evidence. Mocks do not discharge this gate. These are planned tests, not executed evidence or pre-1.0 migration support (`rule:compatibility:pre-one`). Observation follows (`rec:observe:decision`). Its test-site claim remains held under (`open:design:claim-evidence`) and is mapped in (`ledger:design:claim-plan`).

**Open Question (Storage implementation review)** · `open:design:storage-review` Owner: the storage-slice implementer and repository reviewer, with placement acceptance owned by the repository owner. Settlement requires accepted (`proposal:design:storage-placement`), a reviewed PostgreSQL client and transaction/isolation design, a reproducible public-input rebuild procedure, and executed (`verif:design:storage-history`) against the supported beta. Availability, backups and credential custody remain deployment obligations (`conv:storage:ownership`). No schema, driver or provisioning is selected by implication, and a passing document gate does not close this implementation hold. Release support follows (`rule:compatibility:pre-one`).

## Formation, geometry and title · `sec:design:graph`

**Signature (Graph)** · `sig:design:graph` pn-graph offers validate-formation, project-complete-act, partition-dependencies, evaluate-geometry, recognize-settlements and fold-title. Outputs include checked projection witnesses, structural folds, geometry enclosures and boundary-indexed title evidence. It guarantees the family census, identifier algebra, endpoint typing and reference rules, while leaving standing allocation to epoch and authentication realization to the declared adapter. The graph substrate is petgraph on release line 0.8, with reviewed release 0.8.3, licensed MIT OR Apache-2.0. Bite 3 declares the dependency once in the workspace manifest at the latest available 0.8 release, retaining default features std, graphmap, stable_graph, matrix_graph and enabling serde-1; pn-graph inherits that declaration and the lockfile records its resolution. A later release line requires its own reviewed change. Public contracts use the petgraph types below directly, with no wrapper type around the graph. pn-graph validates the domain obligations, including complete projections, on inputs and outputs; arbitrary mutation or serde deserialization does not preserve a previous validation result and requires revalidation before binding use. Release support follows (`rule:compatibility:pre-one`).

| Structure | Public petgraph type | Reason and boundary |
| --- | --- | --- |
| Directed complete projections and their dependency roles, including removable projections and parallel edges | petgraph::stable_graph::StableDiGraph (directed StableGraph) | StableGraph preserves unrelated node and edge indices on removal and supports parallel edges; a removed slot is not a permanent identity and may be reused. |
| Temporary undirected intersection graph of principal dependency closures | petgraph::graph::UnGraph (undirected Graph) | Graph has compact indices suited to a temporary intersection graph built once and read without removals; removal can move the last node or edge into the vacated slot. |
| Projection alternative considered | GraphMap | GraphMap uses Copy + Ord + Hash node weights as keys and does not allow parallel edges, so it does not carry the complete projection multigraph. |

**Algorithm (Formation)** · `alg:design:formation` Validate the identifier constructor and family census, endpoint sorts, structural body and complete projection set; verify author approval and permitted projection removal through the declared authentication operation; resolve mandatory public references and check dependency validity at each authoritative position. Registration anchors its existing Actor/Profile pair rather than minting a new pair. A dangling identifier may be syntactically valid without becoming an anchored standing recipient. The governing surfaces are ``def:graph:identifier-algebra``, ``def:graph:verified-act`` and ``def:graph:act-edge-projection``. Construct a fresh StableDiGraph from the public history in authoritative act order. Insert each structural node at its first occurrence, ordering simultaneous occurrences by identifier-constructor role and then structural identifier; materialize required endpoint nodes before their edges. Within each act, insert distinct projections in constructor-role then structural-edge-identifier order, never from hash-table iteration. Apply authorized removals in authoritative act order, ordering multiple affected edges by structural identifier, and retain the act record and removal evidence. The same public input and operation sequence under the reviewed backend produce the same indices, including any slot reuse; a history-free compacted graph is a different value. These storage choices do not change the authoritative semantics or turn a syntactically present endpoint into an anchored recipient. Release support follows (`rule:compatibility:pre-one`).

**Algorithm (Dependent partition)** · `alg:design:dependency-partition` Against fixed pre-epoch history, compute each proposed act's principal dependency closure, including required co-legs; reject missing dependencies and invalid authoritative placement. Form an intersection graph of these closures and union each connected component. Publish the resulting disjoint blocks and compare their union with the proposed membership. Blocks may interleave in authoritative order; earlier processing cannot discharge another block's obligations. This implements ``def:graph:dependent-act-set``. Use petgraph UnGraph for the temporary intersection graph: insert closure vertices in their parent acts' authoritative order and each intersecting pair once in lexicographic order of those positions. Its weights retain the parent structural identifiers and intersection witnesses. Build it without removals and read connected components as sets; component traversal order cannot affect block membership or replace authoritative ordering. Release support follows (`rule:compatibility:pre-one`).

**Algorithm (Geometry)** · `alg:design:geometry` Apply the census-defined coordinate extraction, structural-field exclusions, slices and tensor construction in the prescribed order, then derive determinant, sign and parity from the canonical path view. Exact coordinate algebra remains exact where closed; nonlinear kernels return certified enclosures. An unresolved determinant sign is indecisive, never an arbitrary routing polarity. Geometry follows ``post:nodes:canonical-tensor-pipeline`` rather than a generic adjacency approximation. Read the validated StableDiGraph weights through structural identifiers and prescribed coordinate roles, preserving every parallel projection and complete co-leg set. Petgraph adjacency order supplies access only; it does not define tensor coordinates, path polarity or a numerical evaluation order.

**Algorithm (Recognition)** · `alg:design:recognition` Enumerate complete Bid/Accept/Ratify candidates with public references to the same Bid and the required exact Accept. Check prior-boundary ownership, the reference-forced handshake chain, and buyer/seller cancellations by finalization epoch; a cancellation at or before Ratify's epoch defeats it. Co-epoch conflicts read membership and epoch, not residual act positions. Recognition implements ``def:graph:settlement-recognition`` independently of sentiment.

**Algorithm (Title fold)** · `alg:design:title` Starting from genesis title, process boundaries in epoch order. No recognized unchallenged candidate leaves title unchanged; a unique candidate transfers title; conflicting candidates are all consumed without transfer. Persist consumption so failed candidates cannot found later recognition, and distinguish ordinary description updates from orphaned title claims. The fold and its prior-owner witnesses implement ``thm:graph:epoch-title-fold`` and ``def:graph:settlement-consumption``. Observation follows (`rec:observe:decision`).

**Decision (Structural meaning before allocation)** · `dec:design:formation-title` Produce formation and title evidence before recipient resolution. Accept and Ratify allocate outward only when mandatory folded coordinates are positive and their recognized, unchallenged settlement actually transfers title; otherwise they resolve home. Retain successful transfer events across later epochs, and never let a sentiment change rewrite title or terminal membership policy substitute for recognition. Realizes (`req:vision:formation-title`); grounded in ``def:graph:identifier-algebra``, ``def:network:admission-closure``, ``def:graph:act-edge-projection``, ``thm:graph:epoch-title-fold``, ``post:epoch:settlement-standing-title-coupling``, ``def:graph:settlement-recognition``. Release support follows (`rule:compatibility:pre-one`). Observation follows (`rec:observe:decision`).

**Invariant (Settlement standing)** · `inv:design:settlement-standing` The compiler consumes the title fold's event evidence, not a separate inference from an Accept edge or current owner alone. This preserves event-persistent settlement contributions while later title changes remain possible. Formation order is retained where required; valid dependency permutations cannot manufacture another title or standing answer (`req:vision:formation-title`).

## Epoch compilation and conserved solve · `sec:design:epoch`

**Signature (Epoch)** · `sig:design:epoch` pn-epoch offers compile-final-state, evaluate-rung, certify-equilibrium, assess-admission and derive-next-schedules. Compilation returns a frozen object with complete projection evidence; certification returns a proved enclosure and rung report; admission returns a final-set verdict. Each operation reads the same immutable ledger and declarations and exposes its premises, numerical limits and attribution paths. Observation follows (`rec:observe:decision`).

**Model (Frozen epoch)** · `model:design:frozen-epoch` The compiled object contains epoch and boundary evidence, ordered accepted-act candidates, the complete final edge set, derived title events, effective declarations, settled burn view, final ledger and increments, fold cells and membership witnesses, recipients, profiles, sparse base rows, source emission, support extrema and rate hull. Standing and admission are absent until their certified transitions complete. Changing any binding field requires a new compilation. Release support follows (`rule:compatibility:pre-one`).

**Algorithm (Ledger completion)** · `alg:design:ledger` Apply every proposed authored-act increment and the price in force to the settled boundary ledger; reject insolvency before solving. Compute final counts, balances and reduced rates with explicit numeraire, preserving all historical charges. Anchored sources have positive counts because Registration is an accepted act. W1 checks the debit accounting and solvency evidence, never incoming transported balance (``post:epoch:act-debit``). Release support follows (`rule:compatibility:pre-one`).

**Algorithm (Fold cells)** · `alg:design:cells` For netting families, partition complete acts by equality of author, family, source, target and full incidence; aggregation-excluded acts become singleton cells. Fold mandatory coordinates and take the geometric mean of their magnitudes once per cell. No mandatory authored coordinates gives coefficient one; exact zero gives coefficient zero without erasing members. Invitation reads folded A-leg u and f only, while its T-leg relevance remains raw context. These are ``def:epoch:standing-fold-cell`` and ``def:epoch:effective-act-contribution``.

**Algorithm (Recipients)** · `alg:design:recipients` Resolve each cell using the paper's family table over anchored Actors. Positive eligible person-directed cells may allocate outward; settlement cells read transfer evidence, Invitation reads revocation, and artifact/control or nonpositive cells resolve home. Revocation uses the latest represented epoch, with revocation winning ties and reinstatement requiring a complete Invitation in a strictly later epoch. This follows ``def:epoch:standing-recipient-resolution`` and ``def:epoch:inviter-revocation``.

**Algorithm (Base allocation)** · `alg:design:base` Start each source row with the positive self-retention base, then add each cell's coefficient weighted by its declared family profile and effective domain weights at its resolved recipient. Validate nonnegative profile entries, unit sum and projection-domain support before accumulation; do not infer an equal split. Keep a sparse ordered row with an explicit diagonal and witnesses to all cells. Normalize only when constructing hop matrices under ``def:epoch:domain-weighted-base-allocation``. Release support follows (`rule:compatibility:pre-one`).

**Decision (Frozen compiler inputs)** · `dec:design:final-state` Compile once from completed membership, final ledger, derived title, effective constants and the declared profile rule. Freeze base allocation and emission throughout certification and solve. Keep authoritative order for formation checks, but make cell construction and standing independent of dependency-compliant permutations when the specified inputs stay fixed. Realizes (`req:vision:final-state`); grounded in ``post:epoch:standing-epoch-set-determinism``, ``post:epoch:standing-memorylessness``, ``prop:deployment:allocation-input-completeness``, ``def:epoch:standing-domain-profile``. Release support follows (`rule:compatibility:pre-one`). Observation follows (`rec:observe:decision`).

**Algorithm (Emission and support)** · `alg:design:emission-support` Compute source emission as the lesser of unity and final balance divided by charged price times action count. Zero-balance sources retain identity rows. Propagate contributing rate extrema through sparse positive base support at each supported depth, respecting source emission and retained diagonal mass; this derives contributing widths before the solve. Support follows the declared depth mass and ``prop:dynamics:support-state-independence``; an enclosure unable to decide a required support predicate must be refined or reported indecisive.

**Algorithm (Transport evaluation)** · `alg:design:transport` For a candidate standing vector, evaluate the safety-wall-clamped activation and hop-dependent tilt, normalize each sparse hop row and apply products in source-adjacent order. Mix the supported products by normalized depth mass, then apply source emission once and add retained identity mass. Transport the balance/count pair and form the reduced mediant with a proved positive denominator. Never damp inside a hop or scale base scores before normalization as a substitute for emission (``def:epoch:finite-depth-conserved-transport``).

**Decision (Conserved pair operator)** · `dec:design:conservation` Publish the complete factorized emitted operator and verify row-stochasticity, pair-mass totals, the export bound and closed-cluster identities. Standing is a ratio of transported pairs; neither its sum nor a transfer of ledger assets is a conservation claim. A sparse implementation is compared against a dense independent small-case operator including retained diagonal mass. Realizes (`req:vision:conservation`); grounded in ``def:epoch:conserved-standing-equilibrium``, ``post:epoch:standing-pair-mass-conservation``, ``rem:epoch:transport-is-not-ledger-transfer``, ``rem:gates:standing-safety-scope``. Release support follows (`rule:compatibility:pre-one`). Observation follows (`rec:observe:decision`).

**Algorithm (Width fence)** · `alg:design:fence` Evaluate the paper's rival factor times wall-gain cap, cumulative tilt at the deepest supported horizon and contributing width with outward bounds. Compare its margined value with unity. Equal contributing width at fixed wall, profile and rung yields the same fence regardless of graph shape; an interval evaluation of a tighter graph-sensitive Jacobian supremum is not a replacement certificate (``def:dynamics:conserved-standing-certificate``). Release support follows (`rule:compatibility:pre-one`).

**Decision (Published finite rung search)** · `dec:design:rung-verdicts` Visit the published finite grid greatest first, independently evaluating every attempted rung using the declared deterministic refinement budget. Record PASS, FAIL or INDECISIVE and the deciding evidence, then select the first proved pass. An indecisive higher rung may be passed over only as the published procedure specifies, never renamed FAIL; the exact zero-tilt anchor supplies the terminal certifying rung. Realizes (`req:vision:rung-verdicts`); grounded in ``def:epoch:tilt-backoff-grid``, ``rem:epoch:certificate-failure-versus-indecisive-enclosure``. Release support follows (`rule:compatibility:pre-one`). Observation follows (`rec:observe:decision`).

**Algorithm (Rung record)** · `alg:design:rungs` The report names the grid edition, ordered attempted rungs, each fence enclosure, precision/refinement steps, budget and verdict, plus the accepted rung. Replay executes the same policy; extra private precision cannot select a different published rung. A local interruption that prevents executing the declared policy produces an incomplete computation, not a fabricated INDECISIVE outcome for an unexecuted rung. Release support follows (`rule:compatibility:pre-one`). Observation follows (`rec:observe:decision`).

**Algorithm (Point solve)** · `alg:design:solve` Use deterministic fixed-point iteration from a declared point inside the invariant hull, applying the frozen conserved map at the accepted rung. ## Numerical design · `sec:design:numbers`

**Model (Exact values and enclosures)** · `model:design:numbers` Structural identifiers, counts, multiplicities, positions and epoch indices are exact discrete values. **Rule (Comparison)** · `rule:design:numeric-comparison` For a required non-strict x greater-than-or-equal-to y comparison, PASS requires a lower bound of x at least the upper bound of y, and FAIL requires an upper bound of x below the lower bound of y.
