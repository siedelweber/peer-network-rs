**Verification (Unserved reader admission)** · `verif:node:admission` The test-only admission harness parses the build-owned schema through the admitted carriage and SDL reader and the independent TOML register draft through its closed reader. It compares roots, fields, result types and nullability; checks closed operation metadata, failure names, applicability and pending capacity admission; and retains only first-party refusal classes. The artifact and draft are embedded and compared byte for byte with their reviewed inputs, including the record’s draft; substituted runtime files are not read. No executor or served configuration is constructed, including for synthetic admitted-limit fixtures. This establishes reader agreement only, not execution bounds, scalar transport or cancellation. Its finite conformance and robustness controls are (`claim:admission:control-schema-register-agree`), (`claim:admission:schema-reader-refuses-invalid-shapes`), (`claim:admission:register-syntax-refuses`), (`claim:admission:register-unknown-keys-refuse`), (`claim:admission:register-metadata-is-closed`), (`claim:admission:pending-register-cannot-serve`), (`claim:admission:embedding-is-build-owned`), (`claim:admission:embedded-child-has-no-policy-path`).

**Verification (Bounded byte executor)** · `verif:node:bounded-executor` The one public byte operation accepts a checked context and bounded transport bytes, rejects pending served construction, and dispatches `start` through the actual GraphQL schema only after byte, lexical, selection and validation admission. Its response uses the shared ordered writer with one separately bounded replacement. Twelve finite, one-process, test-written controls witness (`claim:executor:start-through-bytes`), (`claim:executor:malformed-message-refuses`), (`claim:executor:unsupported-operation-refuses`), (`claim:executor:pending-configuration-refuses`), (`claim:executor:reservation-limit-precedes-work`), (`claim:executor:depth-limit-precedes-expansion`), (`claim:node:lexical-walk-matches-parser`), (`claim:executor:decoding-work-is-independent`), (`claim:executor:result-invariant`), (`claim:executor:message-error-bytes`), (`claim:executor:response-replacement-fits`) and (`claim:executor:response-nothing-fits`). These controls admit no numeric register ceiling, served edition, listener, store or lifecycle result; the independent comparisons, public-entry census and mutants of (`[ROOT-preview:design:first-node-cuts]`) remain owed.

The designed pn executable has explicit `start` and `edition` commands under (`[ROOT-amend:api:health-lifecycle]`); neither accepts an edition argument. Exactly one of `PN_EDITION` and the public edition-only file named by `PN_EDITION_FILE` supplies selection, and both supplied or neither supplied refuses as usage, with no default or precedence. The `edition` command reports the edition, source and embedded-roster support as one JSON object without dispatching start; the roster contains only pairs with both generated artifacts embedded at their assigned coordinates, so the first pair reports supported=false before its register is generated. Supported is not a promise that pn start will start. As a result command it refuses terminal stdout with usage exit 2 and must be piped or redirected; its help states this. The shell refuses both descriptor advertisements and the public `PN_CONNECTION_INPUT` directory-delivery advertisement before acquiring any connection input or directory path; C9 must decide and admit the eventual delivery form. pn start requires the supervisor’s notification socket and cannot be started by hand outside such a supervisor; its help states this. Readiness uses that local notification protocol, and only SIGTERM is graceful termination. These are design contracts, not implemented command surfaces. The initial binary implements actual argument parsing, the origin runner and its terminal help/version/usage paths; `start` and `edition` return runtime `Configuration` at their first unbound environment fact, without an edition read or ready notification. The designed library exposes an opaque checked public bootstrap with a checking constructor, read-only lifecycle state, event/action fact types, an opaque controller with creation/state/event methods, and its context-construction method under (`[ROOT-amend:api:node-package]`). These are non-entry orchestration items: they acquire no capabilities, admit no caller-supplied limits, and execute no operation. The binary alone dispatches the controller’s bounded request bytes through `execute`; the resolver and startup bridge remain private, and the existing `execute` and no-argument `served` signatures stay unchanged. The no-argument constructor never supplies a start-capable context: it keeps `LimitsUnadmitted` while the register is pending and, after generation and admission, refuses with `Configuration` for absent checked bootstrap and controller linkage; only the controller's checked construction path can produce a served context. Completion facts and refusal interpretation remain obligations of the trusted binary, not authenticity guarantees supplied by the public message types. Both the revised entry origin and the executor with variables and the typed parser arm must land before the lifecycle builder starts; that builder edits neither prerequisite. The internal lifecycle, its single byte-entry attempt, notification arbitration, cooperative deadlines and ordered cleanup are specified under (`[ROOT-amend:api:health-lifecycle]`); actual process binding remains the process-adapter subcut. The initial controlled-adapter binary takes the preparation instant, parses arguments and uses the shared runner for terminal output, but an unbound start or edition effect returns runtime Configuration with empty stdout rather than fabricated OS facts. Once the process binding exists, until the initial register is generated with every value admitted, an otherwise valid start returns runtime failure 1 with `LimitsUnadmitted`, empty stdout and no ready notification; earlier usage refusals retain precedence. The designed process adapter binds named environment/file reads, a safe synchronous SIGTERM latch followed by main-thread runtime wakeup, and one unbound nonblocking local readiness send; the shared runner retains actual output and observation ownership throughout. No listener, connection-input acquisition or lifecycle worker is enabled by those bindings. Presentation failure never implies readiness or rollback and never triggers automatic retry. The shell controller starts no worker of its own; the shared observation runner retains its worker and final-status contract.

**Definition (Initial binary boundary)** · `def:node:initial-binary` The `pn` target captures entry origin first, takes a separate monotonic preparation instant, parses actual arguments through `cli-common` and delegates terminal records and exits to the shared runner. **Definition (Checked public bootstrap)** · `def:node:checked-bootstrap` `CheckedBootstrap::new(&PreparationFacts) -> Result<CheckedBootstrap, PreparationRefusal>` validates the selected public edition, reserved-input absence and notification facts before any worker action; its fields remain private and it cannot supply a limit, artifact or start result (`[ROOT-amend:api:node-package]`).

**Definition (Lifecycle state)** · `def:node:lifecycle-state` `Controller::state(&self) -> State` lends inspection of the closed state table; only `Controller::advance` changes state, and inspection grants no readiness authority (`[ROOT-amend:api:health-lifecycle]`).

**Definition (Active lifecycle deadlines)** · `def:node:active-deadlines` `Controller::active_deadlines(&self) -> (Option<u64>, Option<u64>, Option<u64>)` lends only active absolute startup, stopping and cancellation-drain bounds in that order on the supplied monotonic nanosecond timeline; it performs no effect and renews no deadline (`[ROOT-amend:api:health-lifecycle]`).

**Definition (Lifecycle event)** · `def:node:lifecycle-event` `Event` carries bounded supplied facts and byte-entry completion; constructing an event executes no work and cannot authenticate a fabricated ready message (`[ROOT-amend:api:node-package]`).

**Definition (Lifecycle action)** · `def:node:lifecycle-action` `Action` names construction, bounded byte dispatch, cancellation, ordered release, notification and completion requests; inspecting an action performs none of them (`[ROOT-amend:api:node-package]`).

**Definition (Transition refusal)** · `def:node:transition-refusal` `TransitionRefused` is distinct from `EntryError`; an unlisted state/event pair and an out-of-state context request leave the controller without a new effect (`[ROOT-amend:api:health-lifecycle]`).

**Definition (Pure controller)** · `def:node:pure-controller` `Controller::new() -> Controller`, `Controller::state(&self) -> State` and `Controller::advance(&mut self, Event) -> Result<Vec<Action>, TransitionRefused>` own the state, retained cause and deadlines without reading the environment, invoking a resolver or performing an OS effect (`[ROOT-amend:api:node-package]`).
