# Public authentication evidence · `guide:authentication:public-evidence`

**Section (Authentication claim area)** · `sec:authentication:area-authentication` Incorrect public byte recipes or script interpretation can attach authority to the wrong author. The public recipes and fixed-size carriers implement the public subset of (`[ROOT-dec:design:authentication-owner]`) under (`[ROOT-amend:decomposition:act-authentication]`).

**Definition (Conditional public evidence)** · `def:authentication:public-evidence` AssetId stores display-order asset bytes; consensus encodings reverse them explicitly. KeyHash is an opaque declared digest, not a parsed key. Qualification decodes exactly one canonical PNAT script and leaves output and issuance validation to the wallet. Key-script decoding accepts exactly the canonical PNAK script. These byte recipes neither sign, verify a signature, fetch a chain nor authenticate supplied evidence. Hashing an opaque 32-byte encoding follows (`[ROOT-amend:identity:signing-key-hash]`); invalid point refusal belongs to membership and verification. Initial asset derivation follows (`[ROOT-amend:identity:author-asset-recipe]`) through RustCrypto SHA-256 and its compression primitive, independently of Elements' implementation.

**Record (Public recipe evidence)** · `rec:authentication:evidence` The committed golden values in tests/golden.json contain three daemon-issued, signed and mined transactions with known prevouts, contract fields and the daemon's returned asset identifiers. The contract_rpc field is the RPC display spelling; contract is the reversed raw consensus field, checked against the transaction bytes. Regenerate with python3 -B ci/authentication_vectors.py --generate packages/act-authentication/tests/golden.json in the declared Elements service environment. Python hashlib independently supplies the key digests and key scripts; no unit test starts a daemon. (`claim:authentication:asset-identifiers-match-daemon`), (`claim:authentication:key-hashes-and-scripts-match-independent-values`) and (`claim:authentication:qualification-is-one-canonical-script`) check these finite public obligations. They do not establish live token history or close signature dependency admission.

**Definition (Public verification admission)** · `def:authentication:verification-admission` The verification module supplies VerificationKey::parse, VerificationKey::verify and membership_key under (`[ROOT-amend:crypto:authentication-entry]`). A key can be created only by parsing exactly 32 bytes as an x-only point. Verification accepts exactly a 64-byte BIP-340 signature and a 32-byte message digest, with message length checked first and both lengths checked before native work. membership_key parses first, then computes the unchanged key digest; its result is a candidate for comparison, not a token-membership verdict. VerificationError distinguishes KeyLength, InvalidKey, MessageLength, SignatureLength, ContextCapacity and InvalidSignature. It carries no input payload. Public arguments and results are observed in full; no secret exists in this interface. The operations await independent integration review and are not an enabled act verifier.

**Record (Publication validity and wrapper admission)** · `rec:authentication:signature-fixtures` tests/bip340.csv is the complete unchanged nineteen-row BIP-340 publication from bitcoin/bips revision 200f9b26fe0a2f235a2af8b30c4be9f12f6bc9cb, at bip-0340/test-vectors.csv. The publication is available at https://github.com/bitcoin/bips/blob/200f9b26fe0a2f235a2af8b30c4be9f12f6bc9cb/bip-0340/test-vectors.csv. ci/authentication_bip340.py checks its SHA-256, independently computes the tagged challenge with hashlib and the curve equation with Python integers, and agrees with all nineteen published results at their original lengths. (`claim:authentication:published-signatures-have-fixed-message-admission`) verifies valid admitted rows, refuses invalid admitted rows, and gives MessageLength for the four valid messages of 0, 1, 17 and 100 bytes. Nothing pads, hashes or truncates a message to fit. tests/malformed-points.json separates wrong lengths, a point without a curve lift, the field prime and an above-prime encoding; Python independently checks these classes, while the binding's invalid-point causes remain one InvalidKey variant (`claim:authentication:malformed-x-only-points-refuse`). (`claim:authentication:signature-binds-key-and-message`), (`claim:authentication:membership-parses-before-hashing`) and (`claim:authentication:length-admission-precedes-native-verification`) witness association and refusal order. Together with (`[ROOT-claim:discipline:wallet-codec-pins-match-review]`), (`[ROOT-claim:discipline:wallet-codec-provenance-matches-build]`) and (`[ROOT-claim:discipline:authentication-verification-admission-is-reproduced]`), these controls supply the finite evidence of (`[ROOT-verif:crypto:public-verification-fixtures]`). Test-only counters live at the called parsing, hashing and verification boundaries and are thread-local. They add no production observation mechanism.
