# Whole-act partition · `guide:membership:graph`

**Section (Membership)** · `sec:membership:area-membership` Dropping or duplicating an act across dependent blocks changes the proposed whole-act union and can separate a causal ancestor from its dependent. This first increment implements the records-level partition of (`[ROOT-alg:design:dependency-partition]`), using the closure inputs of (`[ROOT-amend:design:bite-one-closure-inputs]`). It does not turn records validation into family formation or authentication.

**Definition (Dependency partition)** · `def:membership:partition` partition_dependencies takes an immutable BoundaryInputs, whose proposed whole acts, principal closures and fixed pre-epoch history were checked by pn-records. It returns petgraph UnGraph directly, with structural root identities as vertex weights and complete intersection identities as edge weights, alongside blocks of whole act identities. Vertices follow authoritative root order; each intersecting pair appears once in lexicographic position order. Connected-component unions must cover the proposed identities exactly once before publication. Block members follow authoritative order and blocks follow their first member; blocks may interleave. Shared parents already in history do not join blocks, and removable declared dependencies do not define them. This realizes network-v0.29.1, ``def:graph:dependent-act-set``, within the internal carrier scope. Missing parents, late parents and incomplete paired acts refuse through records before partition. Backend index exhaustion refuses as Capacity, and an inconsistent union refuses as Coverage; allocation failure and an explicit computation budget are not established by these checks.

**Amendment (Partition evidence)** · `amend:membership:partition-evidence` The records-level part of (`[ROOT-verif:design:closure-partition-cases]`) has these witnesses. (`claim:membership:dependency-closures-partition-the-final-act-set`) establishes the scoped block union with empty, overlapping, interleaved, history-parent and dependency-removal fixtures. (`claim:membership:small-dags-preserve-partition-and-indices`) exhausts the 1024 backward-parent relations on five proposals against a naive ancestor/set-merge oracle, with exact edge intersections and deterministic indices in three presentations. (`claim:membership:partition-publication-requires-exact-cover`) refuses omissions, repetitions, foreign members and empty blocks at the publication guard. (`claim:membership:invalid-records-never-reach-partition`) checks exact upstream causes. (`claim:membership:generated-partitions-match-set-oracle`) and (`claim:membership:shared-partitions-retain-complete-results`) exercise recorded properties and six shared cases; pn-verification independently derives components from direct parent incidence. Both tiers observe the same implementation. Common final-marker selection, target/minimum and maximum-duration boundary evidence, earliest host determination and authenticated family formation remain held under (`[ROOT-open:design:claim-evidence]`).

**Implementation remark (Remaining formation)** · `impl:membership:formation-hold` validate-formation and project-complete-act, family census and endpoint types, authenticated approval and removal, StableDiGraph reconstruction and unrelated-index stability, complete parallel projections and deserialized-state revalidation remain with the rest of (`[ROOT-amend:design:bite-three-step-plan]`). Geometry, graph numeric comparisons and the tensor pipeline are not implemented by this partition. No formation-title claim is minted here. The temporary graph is mutable diagnostic output, not a validated input token. Neither petgraph serde bytes nor Debug output enters canonical publication or binding replay comparison under (`[ROOT-proto:design:encoding]`). There is no graph-byte decoder or publication API in this package.
